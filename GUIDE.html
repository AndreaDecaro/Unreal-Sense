UnrealSense — quick guide

Help for Unreal projects in Visual Studio 2022 and 2026: it tells you where your C++ classes are used in Blueprints, suggests UPROPERTY/UFUNCTION specifiers and flags typical Unreal mistakes as you type. It works with the Unreal Editor closed too.

Install and update

UnrealSense is on the Visual Studio Marketplace.

  1. In Visual Studio open Extensions › Manage Extensions.
  2. Search for UnrealSense and press Install.
  3. Close Visual Studio: the installation finishes and UnrealSense is there when you open it again.

Updates arrive like those of any Marketplace extension: Visual Studio finds them by itself (Extensions › Manage Extensions › Updates shows them) and installs them when you close it. The first time Visual Studio starts after an update, a small What's new in UnrealSense window sums up the important changes, once (minor fixes in one short line; Full changelog opens all the details).

Visual Studio looks for updates only now and then, so UnrealSense also checks for itself when Visual Studio starts. If a newer version is out, the UnrealSense update available window says so: Open Manage Extensions (the update is in the Updates tab and installs when you close Visual Studio), Later (asks again at the next start) or Skip this version (no more reminders until an even newer version comes out). If Manage Extensions does not list the update yet, the Download the .vsix link gets the file: close Visual Studio and double-click it. If an update comes out while Visual Studio is open, a bar at the top of the editor offers the same choices instead of the window (it checks every hour). To turn the reminder off: Tools › Options › UnrealSense › Updates.

Without the Marketplace (offline PCs, blocked sites): close Visual Studio, download UnrealSense-<version>.vsix from the releases, double-click it, tick the Visual Studio versions (2022, 2026) and press Install; to update, do the same with the new file. If your Visual Studio version is not in the list, put Install-UnrealSense.ps1 next to the .vsix and right-click the script › Run with PowerShell. For automatic updates without the Marketplace, add https://andreadecaro.github.io/Unreal-Sense/gallery/atom.xml under Tools › Options › Environment › Extensions, Additional Extension Galleries (if you had added the old address https://assoandrea.github.io/..., replace it: it no longer answers).

License

UnrealSense is free. The license (LICENSE.txt, shown when you install it) lets the author ask for a paid license key in the future, also for copies already installed.

To know that, about every 12 hours the extension downloads a small signed public file (license-policy.json on the project's GitHub Pages): the request contains nothing about you, your PC or your projects. A failed check changes nothing, but the extension must reach that file at least once every 48 hours (directly or through the proxy): past that, its features turn off until a check succeeds (the bar has Check now), even with a license key. If a key is ever needed, a bar in Visual Studio will tell you, with the days left, and the key goes in Extensions › UnrealSense › License.... The same file can ask you to update a version with a security problem: the bar takes you to the new version and, after the stated date, that version stays off until you update it.

First start

Open the project's solution as usual. UnrealSense recognises the project by itself and reads the C++ classes and the Blueprints in a few seconds (the first time it can take a little longer). From then on everything works automatically. View › Output, Show output from: UnrealSense, shows what it is doing.

What you get in the code

How many Blueprints use a class

Next to classes, functions and properties exposed to Blueprints a grey label appears. Click it to see the list of Blueprints.

Find usages in Blueprints

Put the caret on the name of a class, function or property and press Alt+Shift+B (or right-click › Find Blueprint Usages). The Blueprint Usages window opens: double-click a row to open the asset in the running Unreal Editor; the toolbar also has Show in Explorer and Copy reference.

Search text inside Blueprints

Extensions › UnrealSense › Search Text in Blueprints... (or the Quick Menu) opens the Search in Blueprints window: type any text and it lists every Blueprint and data asset that contains it, not only references. For each result you see what it is and where: comment of a comment box or of a node, value typed into a pin (EventGraph › Call PrintString › pin In String), default or tooltip of a variable, widget text, DataTable row, String Table entry, Data Asset property; with Names also names of variables, functions, pins and gameplay tags.

Double-click opens the asset in the Unreal Editor. Options: Match case, Whole word, All assets (also textures, meshes, sounds, animations) and Editor caches (texts the editor regenerates by itself, hidden by default). Assets are read from disk, with the editor closed too: under a second on Lyra.

Information on hover

Hover a specifier (e.g. BlueprintReadWrite) to read its explanation, or the name of a class, function or property to see where it is used in Blueprints.

Suggestions as you type

Inside UPROPERTY(...), UFUNCTION(...), UCLASS(...) etc. Visual Studio offers the specifiers valid for your Unreal version, with their explanation. It works for values too, for example the Category names already used in the project or the function to use in ReplicatedUsing.

Member completion (. and ->)

Type a variable name and a dot: Visual Studio lists the functions and variables of its class (including those of the engine base classes), and the list narrows as you type. It works on local variables, parameters, this, call results (GetOwner()->) and members; private and protected members always appear, with a padlock next to them where they are not accessible (classes and functions declared friend see them as accessible). If the variable is a pointer the dot turns into -> by itself. With TObjectPtr, TWeakObjectPtr, TSharedPtr... the dot stays: the list shows both the pointer's functions (Get, IsValid) and those of the pointed object, and picking one of the latter turns the dot into ->. It also works in engine and plugin files (they are added to the index when you open them).

Name completion (locals, members, types, macros)

Wherever you start typing a name, in .cpp and .h files (function or class body, file level, parameters, template arguments such as TArray<TS, bases : public AAc, constructor initializers, arguments of DECLARE_* macros and of UE_LOG), Visual Studio lists, in order: parameters and local variables; members and nested types of the class and its bases (same access rules, only static ones in a static function); the values of the expected enum after case , State = , State == and in the arguments of a function that takes an enum (Name.Find(TEXT("x"), offers ESearchCase::IgnoreCase); types, functions, variables and namespaces (TSoftObjectPtr, AActor, LogLyra, NAME_None, engine enums such as ESearchCase..., including those of the file not saved yet and those created by macros, such as GetHealth/SetHealth from ATTRIBUTE_ACCESSORS); macros with their parameters (UE_LOG, DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam...); keywords. A member just added in a .h shows up in the .cpp right away, even before you save the header.

After :: it lists the names of the scope: UE::Math::, EMyEnum::, Super::; in a .cpp outside functions void AMyActor:: lists the class's functions to define. After class /struct it offers class names without selecting any. Inside #include " it offers folders and headers. On a dynamic delegate the dot also lists AddDynamic, RemoveDynamic, IsAlreadyBound (or BindDynamic).

Automatic includes: picking a name whose header the file does not see, UnrealSense adds the #include after the last one (before the .generated.h), relative to the module's Public/Classes/Private folder ("GameFramework/Actor.h") or to the file's folder; absolute only if no include folder contains it. A single Ctrl+Z removes both name and include. The list does not open while you declare something (FVector Position), in comments and in strings; Ctrl+Space opens it anyway.

Log and on-screen message templates

No need to remember the syntax of UE_LOG or AddOnScreenDebugMessage. At the start of a line inside a function, type one of these short names and pick it from the list:

TypeYou get
uelog, uewarn, ueerrorUE_LOG(LogMyGame, Log, TEXT("Message")); (verbosity Log, Warning, Error)
uelogfUE_LOG(LogMyGame, Log, TEXT("Message: %s"), *Value);
screenmsgif (GEngine) { GEngine->AddOnScreenDebugMessage(-1, 5.f, FColor::Yellow, TEXT("Message")); }

After a value, type . and pick log, warn, error or screen (at the bottom of the list): Health.log becomes UE_LOG(LogMyGame, Log, TEXT("Health = %f"), Health);. The % part and the argument suit the value's type: %d for int32, %lld for int64, %f for float, true/false for a bool, *Name for an FString, *Location.ToString() for an FVector/FName/FRotator, the object's name for an Actor or another UObject pointer, Num() for an array. When the type is unknown, the argument is highlighted so you can check it.

The log category starts as one your module declares (DECLARE_LOG_CATEGORY_EXTERN, or a DEFINE_LOG_CATEGORY_STATIC in the same file) that the file already includes, otherwise LogTemp: the template never adds an include for it by itself. To use another category, type it in the field and pick it from the list: if the file does not include its header yet, the #include is added then. Once the template is inserted its fields are boxed and the first is selected: type to replace it, Tab / Shift+Tab move between the fields (category, message, time, colour), Enter ends the edit and puts the caret after it, Esc leaves the caret where it is. On-screen messages add #include "Engine/Engine.h" when the file lacks it. One Ctrl+Z removes everything.

Warnings and quick fixes

Typical Unreal mistakes are underlined before you compile: missing or wrong .generated.h include, missing GENERATED_BODY(), wrong A/U/F/E/I prefixes, missing _Implementation, UObject pointers without UPROPERTY or a smart pointer (the garbage collector does not see them) and more. Generic C++ errors too, only where the types are certain: writing to a const variable, member or object (also inside a const method), calling a non-const method on a const object, a member that does not exist, the wrong number of arguments, a private/protected member used where it is not accessible (friends, derived and nested classes respected); and warnings for if (A = B), ; right after if/for/while, X = X; and UE_LOG/FString::Printf with a number of % different from the arguments. When the light bulb appears you can apply the fix with a click (for example it creates the _Implementation body in the .cpp, or adds UPROPERTY() with TObjectPtr). Errors are underlined in red, warnings in yellow and suggestions in blue (colours in Tools › Options › Fonts and Colors, entries "UnrealSense - ..."). Errors and warnings are also in the Error List.

Visual Studio's IntelliSense, on the other hand, reports many errors in Unreal code that do not exist. UnrealSense hides them (squiggles and Error List) when it recognises them as false:

  • IntelliSense could not configure the file: it does not open an #include of a header that exists (for example E1696 on "CoreMinimal.h") and then underlines the whole file (UCLASS, UPROPERTY, DECLARE_...). Only includes that are really missing stay.
  • The .generated.h is missing or old (UHT rebuilds it on the next build): errors on reflection macros, on Super, ThisClass, StaticClass, and on Name_Implementation, Name_Validate, Execute_Name when the header declares the right UFUNCTION.

Real errors stay. The IntelliSense errors in Unreal files option chooses: HideFalse (default), HideAll (no IntelliSense errors: UnrealSense warnings and build errors stay) or ShowAll.

Go to definition

Ctrl+click a name (or the key chosen in Tools › Options › Text Editor › General › "Enable mouse click to perform Go to Definition", for example Alt; or F12, or Alt+G): from a function call to its implementation, from the implementation to the declaration and back, from a variable (member, global, local, parameter) to its declaration, from a type to the class definition. It also works on unsaved code. For BlueprintNativeEvent and RPC UFUNCTIONs it goes to _Implementation or _Validate, from the call too, and back; on names created by a macro (NAME_None, GetHealth) it goes to the macro line. If the UnrealSense index knows nothing there, Visual Studio's Go To Definition runs; with Alt+G outside a known name it switches to the matching file (like Alt+O).

Code colours

UnrealSense colours the project's C++ files by itself, without depending on IntelliSense or Visual Assist.

As you type it colours keywords (also int32), comments and documentation comments, strings, numbers and directives. Reflection macros (UCLASS, UPROPERTY, GENERATED_BODY…) are in bold, with their specifiers, the meta=(…) keys and the values.

The colours of names come from the UnrealSense C++ index, on unsaved code too:

  • UObject types (A…/U…), distinct from value types (FVector);
  • interfaces, enums and their values (also "old style" enums such as ESearchCase and UE_LOG verbosity), typedefs, namespaces;
  • functions, fields, globals, locals and parameters (static ones in italics);
  • macros.

Members exposed to Blueprints are in bold.

To change the colours: Tools › Options › Environment › Fonts and Colors, entries UnrealSense - ….

Find a symbol or a file

Alt+Shift+T (Go to Symbol...) searches the classes, functions, variables, enum values, macros and delegates of the project, its plugins and the engine headers: the initials are enough (GAL finds GetActorLocation), or AFoo::Bar to search inside a class. Ctrl+Shift+T (Go to File...) does the same with files; File.cpp:120 opens at line 120. Ctrl+1/2/3/4 (or Tab) switch between Symbols, Types, Files and In File (the symbols of the open file), Enter opens, Esc closes.

In every search box (Go to, Unreal Explorer, class hierarchy, Quick Menu, override, module and parent-class lists) the words separated by spaces are searched each on its own: shooter char finds what contains at least one of the two, first what contains both. The Fuzzy box of the Go to window (Ctrl+F, Fuzzy search option, on by default) also accepts scattered letters (GAL, shchar) and typos (charcter); off, every word must appear as written.

Alt+M or Alt+Shift+M (Go to Symbol in File...) opens the same window on the In File tab and searches only the open file, including local variables and parameters inside functions (with type and function). With no text it shows the whole file in order, starting from the caret; Tick:: shows only the locals of Tick.

All commands in one menu

Press Alt+Shift+Q (or Extensions › UnrealSense › Quick Menu): a menu opens where the mouse is, with all the UnrealSense commands grouped into search, code, project and tools, each with its shortcut. The commands still act on the text caret: at the top, in small print, the menu shows the name it is on (At caret: ...). Type to filter, pick with the arrows and press Enter; Esc closes. The menu shows only the commands that make sense where the caret is: for example Declare Delegate... only in a header, outside function bodies, comments and strings; Create Implementation only on a declaration that has no body yet; GoTo Implementation/Declaration only on a function name. The shortcuts and the Extensions › UnrealSense menu work everywhere and, in the wrong place, the status bar explains why.

The UnrealSense windows (Unreal Explorer, Find Usages, Blueprint Usages, Go to Symbol/File, Quick Menu and the New Unreal Class, Override and Declare Delegate dialogs) have two themes, from Tools › Options › UnrealSense › General › UI theme: Unreal (default, the Unreal Engine 5 editor style, the same with every Visual Studio theme) or Classic (Visual Studio's colours, font and title bars, following the dark, light, blue or custom theme right away). Open windows switch theme when you save the options.

From .h to .cpp and back

Press Alt+O (or right-click › Switch Header/Source) to open the .cpp of the header you are looking at, or the header of the .cpp. It follows the Unreal module layout (Public\Ui\Menu.h ⇄ Private\Ui\Menu.cpp, also Classes) and works in engine and plugin files too.

Override virtual functions

With the caret inside a class (in the .h, or in one of its functions in the .cpp) press Alt+Shift+V (or right-click › Override Virtual Functions...): the list of inherited virtual functions opens (engine, plugins, project, interfaces). Tick the ones you want: UnrealSense adds the declarations in the .h and, if you leave it ticked, definitions calling Super:: in the .cpp. Engine classes load in the background when you open the project; if you press the key right after, the status bar says they are loading.

Create a function's implementation (Create Implementation)

Write the declaration in the .h, leave the caret on the line (also on the UFUNCTION(...) one) and press Alt+Shift+D, or Ctrl+. › Create implementation of ... (the light bulb appears only if the definition does not exist yet). UnrealSense writes the body in the .cpp next to the definitions of the nearby functions, inside the same #if, and moves the caret there. Selecting several declarations creates them all.

  • BlueprintNativeEvent and Server/Client/NetMulticast RPCs become Name_Implementation; with WithValidation also bool Name_Validate(...) returning true.
  • An override calls the parent version (Super::Name(...), with return if it returns a value) only if an ancestor really implements it (not for interfaces or pure functions).
  • A constructor with const FObjectInitializer& gets : Super(ObjectInitializer).
  • BlueprintImplementableEvent, pure and inline functions and interface events have no definition: the status bar explains why. If the definition already exists, the caret goes there.

Declare a delegate

Put the caret in the header where you want the member (usually an empty line in the public: section), and open Alt+Shift+Q › Declare Delegate... (or Extensions › UnrealSense › Declare Delegate...). In the panel choose:

  • the kind: Single, Multicast, Dynamic, Dynamic Multicast, Sparse or Event (Sparse and Event only with the caret inside the owning class);
  • the name (OnScoreChanged) and the delegate type, which follows the name (FOnScoreChangedSignature) until you change it;
  • the return type, only for Single and Dynamic;
  • up to nine parameters (for dynamic delegates the name is required);
  • whether to also declare the member and the handler signature.

The preview shows the code as you type and warns about errors Unreal would give (for example a comma in a type such as TMap<int32, FString>). Create writes the right DECLARE_..._DELEGATE... macro after the #includes, above the class, and the member at the caret (UPROPERTY(BlueprintAssignable) for dynamic multicast and sparse; for an Event the macro, a public accessor and the private field inside the class); a single Ctrl+Z undoes it all. Copy copies the same code to the clipboard. Under the preview a note explains what the chosen kind is for, and Usage example expands with an example of how to bind, call and unbind it, written with your delegate's names.

Class hierarchy

With the caret on the name of a class or struct open Alt+Shift+Q › Class Hierarchy... (or Extensions › UnrealSense › Class Hierarchy...; the entry appears only on a class name). A drop-down opens where the mouse is, with the class, its base classes from the nearest (for example ACharacter, APawn, AActor, UObject, interfaces included) and the derived classes as a tree, with level lines and, next to each class, how many subclasses it has. Classes with subclasses collapse and expand with a click on the arrow or with ←/→ (Ctrl+←/→ all of them); with more than 40 derived classes only the first level is open at the start. Clicking one (or up/down arrows and Enter) opens its file at the class; typing filters the list (matching classes stay under their parents).

Engine classes come from the UnrealSense C++ index, which knows the engine headers included by the project: bases are always complete, engine derived classes are those of those headers (all of them with Index the whole engine). Derived classes of very common classes such as UObject stop at 2,000. While the index builds, only the project's UCLASS/USTRUCT classes appear.

Base function and overrides

With the caret on a virtual function, an override or a UFUNCTION event, the Quick Menu shows Base and Overrides of X... in place of Class Hierarchy.... While the drop-down is open, the name it refers to (class or function) is highlighted in orange in the editor. The drop-down lists the function, the base functions it overrides up to the one that introduces it (marked origin, for example AActor::BeginPlay) and the overrides in subclasses, as a tree. A BlueprintNativeEvent is followed through its _Implementations: from the caret on ChoosePlayerStart you see its implementation and the subclasses' ChoosePlayerStart_Implementation, and from one of those you get back to the UFUNCTION. For events the Blueprints implementing them appear too; on a BlueprintImplementableEvent the entry is called Blueprint Implementations of X.... Clicking a function opens its file, clicking a Blueprint opens it in the Unreal Editor. It needs the UnrealSense C++ index.

Add an #include or a forward declaration

With the caret on a name open Alt+Shift+Q › Add #include: UnrealSense adds the #include of its header written as in Unreal code ("GameFramework/Actor.h"), after the other includes and before the .generated.h. For a class, struct or enum it is its header; for a variable or function the header declaring it if the file does not see it yet, otherwise the one of its type (TObjectPtr<UMyComponent> Comp → the header of UMyComponent).

In a header Add Forward Declaration appears too: it writes class UMyComponent; (or struct, enum class EMode : uint8;, inside its namespace) after the includes or next to the other forward declarations. Templates, nested classes and enums without an underlying type cannot be declared this way: the status bar says so. It needs the UnrealSense C++ index.

Unreal Explorer

Menu Extensions › UnrealSense › Unreal Explorer (or View › Other Windows). It shows the project's modules, the plugins, the Blueprints grouped by their C++ parent class and the config files, with a search box.

Create a new Unreal class

In Solution Explorer right-click a project or a folder › Add › Unreal Class... (or Extensions › UnrealSense › Unreal Class..., or the New class button of the Unreal Explorer). Choose the name (UnrealSense adds the A/U/F/E prefix), the parent class (Common for the most used ones, All Classes for every class of the project, plugins and engine) and the folder: Public puts the .h in Public and the .cpp in Private.

The path can be in any module (a folder with a .Build.cs, or below it): the project, its plugins, the engine or engine plugins. It starts from the folder of the file open in the editor (or the one selected in Solution Explorer); the ... button opens a picker with the project, plugin and engine source folders as a tree, with modules and plugins marked, and a search by module name.

The files are created like the Unreal Editor's (<MODULE>_API, the right includes, the parent's typical functions), added to the project and opened. If the dependency on the parent's module is missing (for example UMG), a checkbox offers to add it to the .Build.cs. Includes stay red until you run Generate Project Files; the .generated.h exists after the first build.

Settings

In Tools › Options › UnrealSense. In Visual Studio 2026 it is a page of the new settings window (All Settings › UnrealSense, split into sections, with the values you already had); in Visual Studio 2022 it stays the classic page. The most useful ones:

Show Blueprint usage hints Turns the grey labels in the code on or off.
Show hints for unused Blueprint API Also shows "no Blueprint usages" on functions and properties exposed to Blueprints but never used: useful for cleaning up.
Unreal project Set it only if UnrealSense opens the wrong project (it happens with solutions containing more than one).
Tell me when an update is available On by default (Updates section); off, the update window never opens.
IntelliSense errors in Unreal files HideFalse by default hides IntelliSense's false errors; HideAll hides them all; ShowAll keeps Visual Studio's.
Member completion after . and -> On by default: turns off only member completion after . and ->.
Name completion (locals, members, types, macros) On by default: turns off name completion as you type, after :: and inside #include.
Add missing #include On by default: off, picking a name does not add the missing include.
Code templates (uelog, screenmsg, .log) On by default: off, the log and on-screen message templates are not offered.
Don't wait for Visual Studio's C++ list On by default: where UnrealSense offers names it does not ask for IntelliSense's list, so the list appears as soon as our index answers instead of waiting for IntelliSense (slow after a header change or with many projects loaded). Where our index has nothing, Visual Studio's list opens. Off, the list merges the two again (and waits for IntelliSense). Visual Assist is unaffected.
UI theme Unreal by default (Unreal Editor style); Classic uses Visual Studio's colours and follows its theme.
UnrealSense colorization On by default: off, Visual Studio's colours come back, right away in open files too.
Semantic colours from the own index On by default: off, only the colours that do not come from the index stay (tokens and Unreal prefixes).
Go to definition (Ctrl+click, F12) On by default: off, Ctrl+click and F12 go back to Visual Studio.
Use the own C++ index On by default. Member and local variable completion need it (off, there is no completion) and it turns on Find Usages (editor context menu and Extensions › UnrealSense): it finds where a C++ symbol is used with an index of our own, also inside macros (arguments of UE_LOG, check, AddDynamic, body of a project #define, UPROPERTY(ReplicatedUsing = OnRep_X)). The first time UnrealSense has UnrealBuildTool generate the compilation database (about a minute) and the index builds in a few seconds; then the index stays on disk and after every save of a C++ file it rereads only the changed files (if you did not add or remove declarations it reuses the known symbols: with Lyra and the whole engine about 1 second, about 4 if a declaration changes). Usages on objects of an unrecognised type are at the bottom of the results, under Uncertain. Index the whole engine (on by default) adds all the engine sources (about 100,000 files); if you turn it off only the engine headers included by the project are indexed. In Task Manager it shows up as usindex: during a build it uses more memory, then gives it back (for a project like Lyra about 0.3 GB; with the whole engine about 3.5 GB in Task Manager, more with a bigger engine).

If something goes wrong

To report a problem or ask for something new, open an issue on GitHub: github.com/AndreaDecaro/Unreal-Sense/issues. Attach the log (see below) when you can: it contains your projects' paths and names, so read it first and remove what you don't want public.

  • I don't see the counters: wait a few seconds after the solution opens. If you have just saved Blueprints in Unreal, use Extensions › UnrealSense › Rebuild UnrealSense Index.
  • A counter looks wrong: note the class and a Blueprint that uses it, and open an issue with the log file (below).
  • Visual Studio's "Find All References" no longer works: if the Extensions › UnrealSense menu shows Restore Visual Studio Indexing, run it and restart Visual Studio.
  • A shortcut does nothing or something else: another extension uses the same key. In the log the KeyBindingCheck: line says which command uses it; you can change the key in Tools › Options › Environment › Keyboard by searching for UnrealSense..
  • Log to attach to a report: the %LOCALAPPDATA%\UnrealSense\Logs folder (paste the path into File Explorer's address bar) has one file per Visual Studio session, UnrealSense_<date>_<time>_pid<id>.log: attach the one of the session with the problem (usually the newest). The last five sessions are kept. The current session's log is also in Visual Studio under Output › UnrealSense.
  • Visual Studio freezes or closes by itself: also attach Hangs_<date>_<time>_pid<id>.log of the same session: for freezes of 5 seconds or more it contains the UI thread's stack, which shows where Visual Studio is stuck even when UnrealSense is not to blame, and with the WHOLE PROCESS STALLED line whether the whole process stopped.
