# UnrealSense

Unreal Engine productivity for Visual Studio 2022 (17.14+) and Visual Studio 2026: Blueprint and
reflection support, plus C++ editing (colorization, completion, go to definition, Find Usages, Go to Symbol, hierarchies,
refactorings) on UnrealSense's own C++ index, written from scratch for Unreal code.

## Features (v1.0)

| Area | What it does |
|---|---|
| **Blueprint usages** | An offline index of `.uasset`/`.umap` headers (works with the editor closed). For each reflected class, function and property it finds the Blueprints deriving from it, function calls, overridden/implemented events, type references, and property usage matched by name. For properties the hint counts graph usages and overrides apart ("2 Blueprint usages - 3 Blueprint overrides"), and the window shows their **values**: each Blueprint's class default (or what it inherits from a parent Blueprint, or the C++ default), and the values set on placed actors in levels (World Partition external actors included) and in data assets. Shown as end-of-line hints ("12 derived Blueprints", "3 Blueprint usages"), in quick info, and in the **Blueprint Usages** window (`Alt+Shift+B`), whose Detail column names the graph and node of each call, event and variable get/set (`EventGraph › Call Fire`, `FireStinger › Get Volume`). |
| **Search text in Blueprints** | **Search Text in Blueprints...** (Extensions › UnrealSense, Quick Menu; prefilled with the selected text) finds any text inside the project's Blueprints and data assets, not only references: comment boxes, node comments, pin values typed in nodes, variable defaults and tooltips, widget texts, DataTable rows, string tables, data asset properties, and (option *Names*) matching variable/function/pin/tag names. Each result says what the text is and where (`EventGraph › Call PrintString › pin In String`, `Variable Health › tooltip`, `Row Quadruple › DisplayName`), with the localization key of FTexts; double-click opens the asset in the Unreal Editor. Options: *Match case*, *Whole word*, *All assets* (also textures, meshes, sounds, animations), *Editor caches* (engine pin tooltips, compiler messages, generated code the editor rewrites by itself, hidden by default). Assets are read straight from disk, only up to their export data (about 250 MB for Lyra's 6,400 searchable assets, under a second). |
| **Open in Unreal Editor** | Double-click an entry of the **Blueprint Usages** window (or its **Open in Unreal Editor** button) to open the asset in the Unreal Editor that has the project loaded; the status bar then says which graph and node hold the usage (no scripting API of the editor opens a graph or focuses a node). It uses the Python plugin's Remote Execution (local machine only): the first time, UnrealSense offers to enable it, adding `PythonScriptPlugin` to the `.uproject` and `bRemoteExecution=True` under `[/Script/PythonScriptPlugin.PythonScriptPluginSettings]` in `Config/DefaultEngine.ini` (restart the editor afterwards). Files that are read-only because they are not checked out in Perforce are made writable, and UnrealSense lists them so you can check them out. If you decline, or no editor is running or answering, the file is shown in Explorer; **Open Blueprints in Unreal Editor...** in Extensions › UnrealSense asks again. |
| **What the counters understand** | Blueprints deriving through other Blueprints ("via BP_Base") and through C++ subclasses ("via C++ AMyCharacter"), also when the base class is in the engine or an external plugin. Config redirects (`ActiveGameNameRedirects`, `ActiveClassRedirects`, `[CoreRedirects]`). Renamed modules whose redirect is not in a config file (registered from C++ or in a plugin's config) are detected from the classes the assets look for, and logged. Plugins in the project's `Plugins/` folder and in the `.uproject`'s `AdditionalPluginDirectories`. |
| **Reflection completion** | Inside `UCLASS/USTRUCT/UENUM/UINTERFACE/UPROPERTY/UFUNCTION/UPARAM/UMETA(...)`: specifiers, `meta=(...)` keys, and values (`Category` from the project, `ReplicatedUsing`/`BlueprintGetter`/`BlueprintSetter` from the class's UFUNCTIONs with an `OnRep_<Property>` suggestion, `EditCondition`, `Units`, `Config`, `AllowedClasses`/`MetaClass`/`BitmaskEnum`...). The specifier list comes from the installed engine's UnrealHeaderTool sources, and the documentation comes from `ObjectMacros.h`, so both always match your engine version. |
| **Quick info** | Hover a specifier to see its documentation. Hover a reflected class, function or property name to see where it's used in Blueprints. |
| **UHT inspections and quick fixes** | Missing, misplaced or misnamed `.generated.h` include. Missing `GENERATED_BODY()`. Invalid A/U/F/E/I prefixes. Private `BlueprintReadWrite`/`BlueprintReadOnly` without `AllowPrivateAccess`. Conflicting specifiers. `BlueprintPure` with no output. UFUNCTION inside a USTRUCT. `ReplicatedUsing` pointing at a missing UFUNCTION (the fix declares `UFUNCTION() void OnRep_X();` and writes its empty body in the .cpp). Missing `GetLifetimeReplicatedProps` (the fix declares the override and writes its definition in the .cpp: `Super::` call, one `DOREPLIFETIME` per replicated property, `#include "Net/UnrealNetwork.h"`). A `Replicated`/`ReplicatedUsing` property that the existing `GetLifetimeReplicatedProps` never registers (the fix adds its `DOREPLIFETIME` line; silent when the list is filled by a helper function). Missing `_Implementation`/`_Validate` of an RPC or BlueprintNativeEvent (the fix generates the stub in the .cpp). Unknown specifiers, or specifiers missing a value. Suggests `TObjectPtr` instead of raw pointers. `BlueprintAssignable` on a non-dynamic delegate. UObject pointer members with neither `UPROPERTY` nor a smart pointer (invisible to the garbage collector; fixes: `UPROPERTY()` + `TObjectPtr`, or `TWeakObjectPtr`). Generic C++ checks as you type (own index, only where types are surely known): writing a const variable, member or object (also inside a const member function), calling a non-const member function on a const object, a member that does not exist, a call with a number of arguments no overload accepts, a private or protected member used where it is not accessible (friends, derived classes and nested classes respected); a function bound to a delegate (`AddDynamic`, `AddUniqueDynamic`, `BindDynamic`, `AddUObject`, `BindUObject`, `AddRaw`/`AddSP`, `BindUFunction`) whose signature differs from the delegate's `DECLARE_*DELEGATE*` (CPP0232, both signatures in the message; payload arguments counted), and a function bound with `AddDynamic`/`BindDynamic` that is not a `UFUNCTION` (CPP0233, fix: adds `UFUNCTION()` above its declaration); a warning on a lifecycle override that never calls its parent (CPP0231: `BeginPlay`, `EndPlay`, `Tick`, `TickComponent`, `PostInitializeComponents`, `BeginDestroy`, `PostLoad`, `GetLifetimeReplicatedProps`, `NativeConstruct`/`NativeDestruct`, `OnRegister`/`OnUnregister`, `PostEditChangeProperty`..., only when the base is a non-pure engine virtual; a call through `Super::`, `ThisClass::Super::` or the parent's name counts; fix: adds `Super::Name(args);` as the first statement, the last for teardown functions such as `EndPlay`); warnings for `if (A = B)`, a `;` right after if/for/while, `X = X;`, and a `UE_LOG`/`FString::Printf` format whose `%` count differs from the arguments. Results appear as squiggles in their own colours (red errors, yellow warnings, blue suggestions; Fonts and Colors → "UnrealSense - Error/Warning/Suggestion"), light bulbs and Error List entries (suggestions stay out of it). |
| **False IntelliSense errors hidden** | Visual Studio's IntelliSense reports errors that are not real in Unreal code; UnrealSense hides them from the squiggles and the Error List with general rules: when IntelliSense could not configure a file (it cannot open an `#include` of a header that exists, e.g. `E1696` on `"CoreMinimal.h"`), every error of that file is a consequence and is hidden, except real missing includes; when the `.generated.h` is missing or stale (UHT runs at the next build), the errors on reflection macros (`UCLASS`, `UPROPERTY`, `GENERATED_BODY`...), on `Super`/`ThisClass`/`StaticClass` and on `Name_Implementation`/`Name_Validate`/`Execute_Name` of a matching UFUNCTION are hidden. Real errors stay. Option *IntelliSense errors in Unreal files*: `HideFalse` (default), `HideAll` (no IntelliSense error: UnrealSense's inspections and build errors stay), `ShowAll`. |
| **Navigation** | **Go to definition** with `Ctrl+click` (or `Alt+click`/`Ctrl+Alt+click` when that modifier is chosen in Tools › Options › Text Editor › General › *Enable mouse click to perform Go to Definition*), `F12` or `Alt+G` (own C++ index): a function call goes to its implementation, an implementation to its declaration and back, a variable (member, global, local, parameter) to its declaration, a type to its definition, also in unsaved code; a BlueprintNativeEvent/RPC goes to `_Implementation`/`_Validate` and back to the UFUNCTION. When the index knows nothing at the click, Visual Studio's own Go To Definition runs (option *Go to definition (Ctrl+click, F12)*). `Alt+O` (**Switch Header/Source**, also in the editor's context menu) opens the `.cpp` of a header or the header of a `.cpp`, following the module's `Public`/`Classes` ⇄ `Private` layout, for engine and plugin files too; `Alt+G` does the same when the caret is not on a reflected symbol. The **Unreal Explorer** window lists modules (`.Build.cs`, dependencies, reflected types), plugins, Blueprints grouped by C++ parent, and config files, with a search box. |
| **Class hierarchy** | With the caret on a class or struct name, *Class Hierarchy...* in the Quick Menu (`Alt+Shift+Q`, or Extensions › UnrealSense) opens a drop-down at the mouse pointer (the class name is boxed in amber in the editor while it is open; the same for *Base and Overrides*) with the class, its base classes (nearest first, indented: `ACharacter`, `APawn`, `AActor`, `UObject`..., interfaces included) and its derived classes as a tree with guide lines and, next to each class, how many subclasses it has. Classes with subclasses collapse and expand (click the arrow, or Left/Right; Ctrl+Left/Right for all); with more than 40 derived classes only the direct subclasses start expanded. Click one (or Up/Down and Enter) to open its file at the class; type to filter (matches keep their parent classes, for context). Engine and plugin classes come from the own C++ index; without it (still building, or off) the project's UCLASS/USTRUCT types are listed. Classes deriving from very common bases (`UObject`) are listed up to 2,000. |
| **Base and overrides** | With the caret on a virtual function, an override or a `UFUNCTION` Blueprint event, the Quick Menu shows *Base and Overrides of X...* in place of *Class Hierarchy...*: the function, the functions it overrides up to where it is first declared (marked *origin*), and its overrides in the subclasses as a tree. A `BlueprintNativeEvent` is followed through its `_Implementation` overrides, and on a `BlueprintNativeEvent` or `BlueprintImplementableEvent` (*Blueprint Implementations of X...*) the Blueprints implementing it are listed too: click one to open it in the Unreal Editor. Needs the own C++ index. |
| **Override virtual functions** | `Alt+Shift+V` (or the light bulb on a class name, or the editor context menu) lists the virtual functions the class at the caret inherits from its engine, plugin and project bases and from implemented interfaces, grouped by declaring class, with a filter. Only the functions you check are added: `virtual ... override;` in the class (under the parent's access, inside the same `#if WITH_EDITOR` blocks) and, optionally, definitions calling `Super::` at the end of the `.cpp`. BlueprintNativeEvents and RPCs are offered as their `_Implementation`; final, deprecated and already overridden functions are left out. |
| **Create implementation** | `Alt+Shift+D` (or the light bulb on a declaration with no definition yet) writes the `.cpp` body of the function declared at the caret in a header (select several declarations to do them all). Unreal's names are used: a BlueprintNativeEvent or a `Server`/`Client`/`NetMulticast` RPC becomes `Name_Implementation`, `WithValidation` adds `bool Name_Validate(...)` returning `true` (only the missing ones are written); a BlueprintImplementableEvent, a pure virtual or an interface event gets none. An override calls the parent version (`Super::Name(...)`, or `return Super::Name(...)`) when an ancestor really implements it (not for interface or pure functions); a constructor taking `const FObjectInitializer&` gets `: Super(ObjectInitializer)`. The definition goes next to the definitions of the neighbouring declarations, inside the same `#if`, and the caret lands in its body; if it already exists, the caret goes there. |
| **Generate getters/setters and constructor** | In a header, with the caret in a class or struct: *Generate Getters/Setters...* (editor context menu, Quick Menu, light bulb on the class name or on a `UPROPERTY`; no shortcut) lists the getters and setters its data members (with or without `UPROPERTY`) do not have yet, the member at the caret ticked. Unreal conventions: `bool bDead` (or a `uint8 bDead : 1` flag) gives `IsDead()`/`SetDead(bool bInDead)` (`bHasKey` gives `HasKey()`), `TObjectPtr<T>` is returned and set as `T*`, numbers, pointers, enums, `FName`, `TSubclassOf` and a few small structs by value, `FString`, structs and containers as `const T&`; `const` and reference members get no setter, static members none at all, and a name the class already declares is skipped. Written at the end of the class in a `public:` section (inside the member's `#if` when it has one), inline, or declared there and defined in the `.cpp` next to the neighbouring definitions. *Generate Constructor* (same places, no shortcut) declares the default constructor after the first `public:` when the class has none (so no other member changes access) and defines it in the `.cpp`, or fills the existing body (inline, or its `.cpp` definition, `FObjectInitializer` one included) with what it still misses: `PrimaryActorTick.bCanEverTick = true;` for an actor that overrides `Tick` (`PrimaryComponentTick` for a component with `TickComponent`), and `X = CreateDefaultSubobject<T>(TEXT("X"));` for each `UPROPERTY` component pointer not assigned yet; the first scene component becomes `RootComponent` when the parent is `AActor`/`APawn`/`AInfo` and the body sets none, the others `SetupAttachment(RootComponent)`. The components' headers are included (module-relative, as Unreal writes them). Classes are told apart by their bases in the New Class catalog (project and engine). Log lines start with `GenerateMembers:`. |
| **Add #include / forward declaration** | With the caret on a name, *Add #include* in the Quick Menu (`Alt+Shift+Q`, or Extensions › UnrealSense) adds the `#include` of its header, written as Unreal code writes it (`"GameFramework/Actor.h"`): for a class, struct or enum its own header; for a variable or function the header declaring it when the file does not see it yet, otherwise the header of its type (`TObjectPtr<UMyComponent> Comp` → `UMyComponent`'s header, `GetWorld()` → `UWorld`'s). The line goes after the other includes, before the `.generated.h` one. In a header, *Add Forward Declaration* also appears: it writes `class UMyComponent;` (`struct`, `enum class EMode : uint8;`, inside its namespace if it has one) after the includes or next to the header's other forward declarations. Templates, nested classes and enums without an underlying type cannot be forward-declared: the status bar says so. Needs the own C++ index. |
| **Declare delegate** | *Declare Delegate...* (Quick Menu `Alt+Shift+Q`, or Extensions › UnrealSense) opens a panel to build a delegate: kind (Single, Multicast, Dynamic, Dynamic Multicast, Sparse, Event), name, type (`F<Name>Signature` by default), return type (only where Unreal allows it) and up to nine parameters, with a live preview. **Create** writes the right `DECLARE_..._DELEGATE` macro after the `#include`s, just above the class at the caret, and the member at the caret (`UPROPERTY(BlueprintAssignable)` for dynamic multicast and sparse delegates; for an Event, the macro, a public accessor and private storage inside the class), optionally with the handler's signature (`UFUNCTION()` for dynamic delegates); one undo removes it all. **Copy** puts the same text on the clipboard. Under the preview, a short note says what the chosen kind is for, and *Usage example* expands into how to bind, call and unbind it, written with your delegate's names. Errors Unreal would report (parameter names missing on a dynamic delegate, a comma in a type, a return value on a multicast) are shown before writing. |
| **New Unreal Class** | **Unreal Class...** (Solution Explorer › Add on a project or folder, Extensions › UnrealSense, or the Unreal Explorer's **New class** button) opens a dialog: class name, parent from **Common** (Actor, Character, Actor Component, Interface, Struct, Enum, Empty, subsystems, User Widget...) or **All Classes** (project, project plugins, engine and the engine plugins the project enables, read in the background and cached), base folder Root/Public/Private and path. The path can be in any module (a folder with a `.Build.cs`, or below one): the project, its plugins, the engine or an engine plugin. It starts at the folder of the file open in the editor (or of the folder selected in Solution Explorer), and the **...** button opens UnrealSense's own folder picker: the source folders of the project, its plugins and the engine as a tree with modules and plugins marked, or the modules matching a search. It writes the `.h` (in `Public`) and `.cpp` (in `Private`) like the Unreal Editor: prefixed name (`A`/`U`/`F`/`E`, `UMyX`+`IMyX` for interfaces), `<MODULE>_API`, `CoreMinimal.h`, the parent's header and the `.generated.h`, with the engine's own templates (constructor, `BeginPlay`, `Tick`, `SetupPlayerInputComponent`, `TickComponent`, subsystem `Initialize`/`Deinitialize`...). Structs and enums are header only. If the module's `.Build.cs` does not depend on the parent's module (e.g. `UMG`, `DeveloperSettings`), it offers to add it. The files are added to the game's `.vcxproj` under the matching filter and opened (files of engine modules and engine plugins are only opened: adding them to `UE5.vcxproj`, ~120,000 items, blocks Visual Studio for seconds per file, and **Generate Project Files** adds them); IntelliSense resolves their includes after the next **Generate Project Files** (UBT's Makefile projects cannot give a new file its module's include paths without reloading the project). With a `.uproject` (or a folder) open instead of a solution there is no `.vcxproj`: the files are only created and opened, the folder view shows them and UBT builds them without Generate Project Files. |
| **Call hierarchy** | `Alt+Shift+H` (or *Call Hierarchy...* in the editor context menu, the Quick Menu on a function, or Extensions › UnrealSense) opens the Call Hierarchy window on the function at the caret: who calls it, each caller expandable to its own callers, level by level. Each row shows the function, its class, file:line and the call line (`×3` when it calls more than once; the tooltip lists every call). Calls through a base virtual function (`ABase::Fire()` on a pointer that may hold your class) and through a Blueprint event are marked *possible via ...*; qualified calls such as `Super::Fire()` are not. Recursion is shown once, marked *(recursive)*. A `UFUNCTION` called from Blueprints lists those Blueprints too (with the graph and node once read): double-click opens one in the Unreal Editor. *Calls from* switches to what the function calls. Enter or double-click goes to the call; the search box filters the loaded rows. Only real calls count: declarations, `&AFoo::Bar` and calls in UHT's generated files are left out. Needs the own C++ index. Log lines start with `CallHierarchy:`. |
| **Include hints** | At the end of each `#include` line, how many times the file uses what that header brings in ("9 uses"): the types, functions, variables and enum values the own C++ index resolves through declarations the header reaches (directly or through the headers it includes), and the macros it defines. Each use counts once, for the include nearest to its declaration: the header that declares it, else the one reaching it in the fewest `#include` steps (the first one on a tie); a type counts by its body, a forward declaration only when no body is reachable. Clicking the hint lists those places in the Find Usages window; double-click one to go there. "No use found" marks an include nothing seems to need (it may still be needed: some macros and templates are not tracked). Counted again a moment after you stop typing. The `.generated.h` include and unresolved includes show nothing. Needs the own C++ index. Option: Find Usages (own index) › Show include hints. Log lines start with `IncludeHints:`. |
| **Rename symbol** | `Alt+Shift+R` (also the editor context menu and the Quick Menu) renames the function, variable, local, parameter, class, struct or enum at the caret everywhere the own C++ index resolves it: the whole override tree of a virtual function, Unreal's `_Implementation`/`_Validate` of a BlueprintNativeEvent or RPC, a class's constructors and destructor. Locals and parameters are found in the open file only, keeping same-named locals of other scopes apart. Symbols declared in the engine (or overriding one the index does not know) are refused. The dialog checks the new name as you type (C++ identifier, keyword, Unreal prefix, `b` for bools) and offers: a **CoreRedirect** in `Config/DefaultEngine.ini` for reflected classes, structs, enums, properties and functions (checked by default when Blueprints use the symbol, with their count), renaming the related symbols, renaming the class's `.h`/`.cpp` (with the `#include` lines and the `.generated.h` include), renaming in comments and strings, and how to apply: edit open documents (undoable with Ctrl+Z) and write the other files to disk, or open every changed file in the editor unsaved. **Preview** lists every change by file with a checkbox each; names inside a `#define` body and same-named identifiers the index could not resolve are listed unchecked, with the reason. Files with unsaved changes are offered for saving first (the index reads saved files). Read-only files (Perforce) are made writable and listed in the summary for check-out; renamed files need `p4 move` (or reconcile) and Generate Project Files. Log lines start with `Rename:`. |
| **Introduce Variable / Extract Method** | *Introduce Variable* (editor context menu, Quick Menu, light bulb on a selection; no shortcut) turns the selected expression, or the call chain at the caret (`GetOwner()->GetActorLocation()`), into `const FVector ActorLocation = GetOwner()->GetActorLocation();` on its own line before the statement and puts the name in its place. The type comes from the own C++ index (the return or declared type as written: pointers as `T*`, a `TObjectPtr<T>` as `T*`, references kept, `const` unless a method is called on it, `auto` when unknown); the name from the call or the type (`GetOwner()` → `Owner`, `b` prefix for bools), made unique among the function's names and the class's members. When the same expression occurs again in the function, choose to replace all of them (declared before the first). Refused in loop conditions, in an `if`/`else` body without braces and in macro arguments (`UE_LOG` excepted). *Extract Method...* (same places, `.cpp` files) moves the selected whole statements to a new function: locals used inside become parameters (numbers, enums and pointers by value, other types `const&`, a reference when the statements change them), the one local declared inside and used after becomes the return value; a private member function (declared at the end of the class in its header, defined after the current function) — `static` when no member is used, `const` when none is changed — or a `static` function of the file for a free function. A dialog takes the name and shows the signature. Refused with the reason for part of a statement, a `return`/`goto`/`break`/`continue` leaving the selection, two locals used after it, case labels, a lambda or a macro's arguments. Each file is one Ctrl+Z; a closed header is written to disk (made writable for Perforce). Log lines start with `IntroduceVariable:` / `ExtractMethod:`. |
| **Sort members** | *Sort Members...* (header context menu, Quick Menu; no shortcut) orders the members of the classes in the header, or only the selected members of the class around the selection: methods first or properties first (constructors and destructor lead the methods), then, among themselves, as declared, by name or by size: *padding* puts the properties in decreasing alignment so that the compiler leaves no holes between them (sizes estimated from the type: built-in types, pointers, Unreal containers and math types, enums of the file by their underlying type, other `E` types as `uint8`, other structs as 8-byte aligned; static members last; methods keep their order), always inside their access section. Comments right above a member, its `UPROPERTY`/`UFUNCTION` line and a trailing comment move with it; an `#if ... #endif` block moves as one piece. Nested types, `using`/`typedef`, `DECLARE_*` macros, `GENERATED_BODY`, other directives, `//~ Begin`/`//~ End` markers and comments followed by a blank line stay where they are and split the members into groups sorted separately (a group comment with no blank line under it counts as the next member's comment). Options in the dialog: a blank line between two members that have none (on by default; fields and methods alike, also where nothing moved), merge repeated `public`/`protected`/`private` sections into the first of each (with a selection, only the sections it holds whole; not past a type declared between them), and reorder the definitions in the matching `.cpp` (only consecutive definitions of the same class swap places, `_Implementation`/`_Validate` follow their function). One Ctrl+Z undoes the header; every result is checked to hold exactly the same code and comments before it is applied. Reordering properties changes their initialization order and their order in the Details panel. Choices are saved under the options category Sort Members. Log lines start with `SortMembers:`. |
| **Log categories** | Inside `UE_LOG(`, `UE_LOGF(`, `UE_LOGFMT(` and `UE_CLOG(` (after the condition) the completion list offers the log categories declared with `DECLARE_LOG_CATEGORY_EXTERN`/`DECLARE_LOG_CATEGORY_CLASS` or this file's `DEFINE_LOG_CATEGORY_STATIC`: your module's first, then the project's and its plugins', then the engine's; choosing one the file does not include adds its `#include`. The next argument lists the verbosities (`Log`, `Warning`, `Error`, `Display`, `Verbose`, `VeryVerbose`, `Fatal`; `All`/`NoLogging` in category declarations). Go to definition on a category goes to its `DECLARE_LOG_CATEGORY_EXTERN` (from there, to its `DEFINE_LOG_CATEGORY`). Warnings: a category used in a `.cpp` that nothing declares in the project, its plugins or the engine, or that is another `.cpp`'s `DEFINE_LOG_CATEGORY_STATIC` (CPP0221; fix: define a static category in this file); a `DECLARE_LOG_CATEGORY_EXTERN` with no `DEFINE_LOG_CATEGORY` anywhere in its module, which fails at link time (CPP0222; fix: adds `DEFINE_LOG_CATEGORY(Name);`, and the `#include` if needed, to the `.cpp` named like the header or the module's main `.cpp`). Go to Symbol lists categories too. Log lines start with `LogCategories:`. |
| **Console variables** | Console variables and commands registered in C++ (`TAutoConsoleVariable`, `FAutoConsoleVariableRef`, `FAutoConsoleCommand...`, `IConsoleManager::Get().RegisterConsoleVariable/Ref/Command`) in the project, its plugins and the engine (its `.cpp` files too, with the option *Index the whole engine*) are found by their console name in **Go to Symbol** (`Alt+Shift+T`: `r.shadow`), with type, default and help next to the name. Hovering a string naming one (`TEXT("r.ScreenPercentage")`) shows its type, default and help; go to definition on it opens its declaration; inside `FindConsoleVariable(TEXT("` / `FindTConsoleVariableData...` the names are completed. `[ConsoleVariables]` and `[SystemSettings]` keys of `.ini` files complete them too. Log lines start with `CVars:`. |
| **Sort #includes** | *Sort #includes* (context menu of `.h` and `.cpp` files, Quick Menu; no shortcut), or the *Also sort the #include lines* box of Sort Members, puts the `#include` lines in alphabetical order (case-insensitive; with a selection, only the selected lines). Each run of consecutive includes is sorted on its own: a blank line, a comment, an `#if` or code between them keeps your groups and conditional includes apart. Unreal's order is kept: in a `.cpp` its own header goes first, `CoreMinimal.h` stays at the top, the `.generated.h` stays last, `<system>` includes come after the quoted ones; commented-out includes do not move. One Ctrl+Z undoes it. Log lines start with `SortIncludes:`. |
| **Remove Unused #includes** | *Remove Unused #includes...* (context menu of `.h` and `.cpp` files, Quick Menu; no shortcut) lists the file's `#include` lines: those the index allows removing have a check box (ticked when they can all go together), the others are greyed out with the reason they stay. A line can go only when everything the file uses keeps its declaration in reach through the other includes: names, the types of the variables and functions it uses (a member typed `TObjectPtr<UFoo>` needs UFoo's header even when the file never writes UFoo), macros, and names the index could not resolve. In a header, the same is checked for every project file including it, directly or not (at most 64; more and the header is left alone). Never offered: a `.cpp`'s own header, `CoreMinimal.h`, the `.generated.h`, includes inside `#if`/`#ifdef` blocks or braces, non-header files (`.inl`), lines marked `// IWYU pragma: keep`/`export` or `NOLINT`, unresolved includes, and every line of a file that uses a name no include brings (it compiles through the precompiled header: the index cannot tell which line matters). Needs the own index with the engine (engine headers not indexed are refused). Removed in one edit (Ctrl+Z), Perforce files made writable. On an `#include` whose hint says *no use found* and that can go, the light bulb offers *Remove unused #include*. The index sees one build configuration: build once after removing. Log lines start with `UnusedIncludes:`. |
| **Member completion** | After `.` and `->` it lists the functions and variables of the expression's class, its bases included (engine ones too), as you type: locals, parameters, `this`, call results such as `GetOwner()->`, members, template instances. Private and protected members are always listed, with a lock where they are not accessible (classes and functions declared `friend` count as having access). ### Own C++ index (on by default)

**Own C++ index** (`Use the own C++ index` in the options, category "Find Usages (own index)"):
member completion and name completion (above) and Find Usages from UnrealSense's own C++ indexer, written from scratch (no compiler). It runs as a separate process
(`OwnIndexer\usindex.exe`, shipped in the VSIX with its own .NET runtime), indexes the project and the engine headers it
includes in a few seconds, keeps the index on disk and updates it incrementally after C++ files are saved, and after files change on disk
outside Visual Studio (a Perforce or git sync, a branch switch: one update about 3 seconds after the changes stop; only the changed
files are read again; when the saved files declare nothing new, the previous symbol table is reused: Lyra with the whole
engine about 1 s, about 4 s when a declaration changed), and also while you type in a header: a member added to a `.h` is known to completion and go to
definition in its `.cpp` before the header is saved (a completion asked right after waits for that update, at most 4 seconds). It reads each file's include paths and definitions from UnrealBuildTool's compile database, which
UnrealSense generates on the first start and again when the build rules change or a source file is added (about a minute).
Turning the option off also turns both completions off. With the option on, **Find Usages** appears in the editor's context menu and under Extensions › UnrealSense. It also lists uses
inside macros: in macro arguments (`UE_LOG`, `check`, `AddDynamic`...), in the body of a project `#define` (resolved where the macro is
expanded) and in `UPROPERTY(ReplicatedUsing = OnRep_X)` / `BlueprintGetter` / `BlueprintSetter`. Names that macros build
from their arguments are known too: the `NAME_None`/`NAME_*` constants, the accessors of `ATTRIBUTE_ACCESSORS(UMyAttributeSet, Health)`
(`GetHealth`, `SetHealth`, `InitHealth`, `GetHealthAttribute`: go to definition leads to the macro line), stat and Slate argument
macros; the verbosity of `UE_LOG` (`Warning`, `Log`...) is the `ELogVerbosity` value. Unreal's old-style enums
(`namespace ESearchCase { enum Type {...} }`) are coloured and listed as enums.
`Index the whole engine` (on by default) also indexes every engine and plugin source file (about 100k files); turn it off to
index only the engine headers the project includes. Between builds the process
gives back the memory a build used: what stays is the index and what completion needs (Lyra, project index: about 0.3 GB;
whole engine: 2.4 GB of managed heap, about 3.5 GB in Task Manager; more with a larger engine); each build logs
`memory after the build: managed heap …, working set …`, and the save once the editor is idle logs `memory after the save:`. Log lines start with
`OwnIndex:`. Uses on an object whose type the indexer cannot infer are listed apart, under "Uncertain" at the bottom of the
results, instead of being guessed. The code lines in the results are coloured with the editor's colours (Tools › Options ›
Fonts and Colors: keywords, strings, comments, macros, Unreal types, calls, members), the searched name in bold.

## Installing and updating

UnrealSense is on the
[Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=AndreaDecaro.UnrealSense): in Visual
Studio open Extensions › Manage Extensions, search for **UnrealSense**, press **Install** and close Visual Studio to
finish. Updates arrive like those of any Marketplace extension; after one, the first Visual Studio start shows a short
**What's new in UnrealSense** window, once (only the important changes; the full changelog is linked).
Visual Studio looks for extension updates only now and then, so UnrealSense also checks the latest release itself at
startup: when a newer version exists, an **UnrealSense update available** window opens Manage Extensions, reminds you
at the next start, or skips that version (a link downloads the `.vsix` when Manage Extensions does not list it yet).
While Visual Studio stays open it checks again every hour, and a release published meanwhile shows an info bar with the
same choices. Option: Updates › Tell me when an update is available. Log lines start with
`Update:`.

Without access to the Marketplace (offline PCs, blocked sites), download `UnrealSense-<version>.vsix` and
`Install-UnrealSense.ps1` from the [GitHub releases](https://github.com/AndreaDecaro/Unreal-Sense/releases). Run the
script (it picks the highest version next to it and installs it into the newest Visual Studio), or double-click the
`.vsix`; to update, install the new one over the old. For automatic updates without the Marketplace, add
`https://andreadecaro.github.io/Unreal-Sense/gallery/atom.xml` under Tools › Options › Environment › Extensions ›
Additional Extension Galleries (if you added the old `https://assoandrea.github.io/...` address, replace it: it no
longer answers).

Guide: [GUIDE](https://andreadecaro.github.io/Unreal-Sense/GUIDE.html). Bugs and requests:
[issues](https://github.com/AndreaDecaro/Unreal-Sense/issues).
