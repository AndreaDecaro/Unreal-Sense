# UnrealSense

Unreal Engine productivity for Visual Studio 2022 (17.14+) and Visual Studio 2026: Blueprint and
reflection support, plus C++ editing (colorization, completion, go to definition, Find Usages, Go to Symbol, hierarchies,
refactorings) on UnrealSense's own C++ index, written from scratch for Unreal code.

## Features (v1.0)

| Area | What it does |
|---|---|
| **Blueprint usages** | An offline index of `.uasset`/`.umap` headers (works with the editor closed). For each reflected class, function and property it finds the Blueprints deriving from it, function calls, overridden/implemented events, type references, and property usage matched by name. Shown as end-of-line hints ("12 derived Blueprints", "3 Blueprint usages"), in quick info, and in the **Blueprint Usages** window (`Alt+Shift+B`). |
| **Search text in Blueprints** | **Search Text in Blueprints...** (Extensions › UnrealSense, Quick Menu; prefilled with the selected text) finds any text inside the project's Blueprints and data assets, not only references: comment boxes, node comments, pin values typed in nodes, variable defaults and tooltips, widget texts, DataTable rows, string tables, data asset properties, and (option *Names*) matching variable/function/pin/tag names. Each result says what the text is and where (`EventGraph › Call PrintString › pin In String`, `Variable Health › tooltip`, `Row Quadruple › DisplayName`), with the localization key of FTexts; double-click opens the asset in the Unreal Editor. Options: *Match case*, *Whole word*, *All assets* (also textures, meshes, sounds, animations), *Editor caches* (engine pin tooltips, compiler messages, generated code the editor rewrites by itself, hidden by default). Assets are read straight from disk, only up to their export data (about 250 MB for Lyra's 6,400 searchable assets, under a second). |
| **Open in Unreal Editor** | Double-click an entry of the **Blueprint Usages** window (or its **Open in Unreal Editor** button) to open the asset in the Unreal Editor that has the project loaded. It uses the Python plugin's Remote Execution (local machine only): the first time, UnrealSense offers to enable it, adding `PythonScriptPlugin` to the `.uproject` and `bRemoteExecution=True` under `[/Script/PythonScriptPlugin.PythonScriptPluginSettings]` in `Config/DefaultEngine.ini` (restart the editor afterwards). Files that are read-only because they are not checked out in Perforce are made writable, and UnrealSense lists them so you can check them out. If you decline, or no editor is running or answering, the file is shown in Explorer; **Open Blueprints in Unreal Editor...** in Extensions › UnrealSense asks again. |
| **What the counters understand** | Blueprints deriving through other Blueprints ("via BP_Base") and through C++ subclasses ("via C++ AMyCharacter"), also when the base class is in the engine or an external plugin. Config redirects (`ActiveGameNameRedirects`, `ActiveClassRedirects`, `[CoreRedirects]`). Renamed modules whose redirect is not in a config file (registered from C++ or in a plugin's config) are detected from the classes the assets look for, and logged. Plugins in the project's `Plugins/` folder and in the `.uproject`'s `AdditionalPluginDirectories`. |
| **Reflection completion** | Inside `UCLASS/USTRUCT/UENUM/UINTERFACE/UPROPERTY/UFUNCTION/UPARAM/UMETA(...)`: specifiers, `meta=(...)` keys, and values (`Category` from the project, `ReplicatedUsing`/`BlueprintGetter`/`BlueprintSetter` from the class's UFUNCTIONs with an `OnRep_<Property>` suggestion, `EditCondition`, `Units`, `Config`, `AllowedClasses`/`MetaClass`/`BitmaskEnum`...). The specifier list comes from the installed engine's UnrealHeaderTool sources, and the documentation comes from `ObjectMacros.h`, so both always match your engine version. |
| **Quick info** | Hover a specifier to see its documentation. Hover a reflected class, function or property name to see where it's used in Blueprints. |
| **UHT inspections and quick fixes** | Missing, misplaced or misnamed `.generated.h` include. Missing `GENERATED_BODY()`. Invalid A/U/F/E/I prefixes. Private `BlueprintReadWrite`/`BlueprintReadOnly` without `AllowPrivateAccess`. Conflicting specifiers. `BlueprintPure` with no output. UFUNCTION inside a USTRUCT. `ReplicatedUsing` pointing at a missing UFUNCTION. Missing `GetLifetimeReplicatedProps`. Missing `_Implementation`/`_Validate` (the fix generates the stub in the .cpp). Unknown specifiers, or specifiers missing a value. Suggests `TObjectPtr` instead of raw pointers. `BlueprintAssignable` on a non-dynamic delegate. UObject pointer members with neither `UPROPERTY` nor a smart pointer (invisible to the garbage collector; fixes: `UPROPERTY()` + `TObjectPtr`, or `TWeakObjectPtr`). Generic C++ checks as you type (own index, only where types are surely known): writing a const variable, member or object (also inside a const member function), calling a non-const member function on a const object, a member that does not exist, a call with a number of arguments no overload accepts, a private or protected member used where it is not accessible (friends, derived classes and nested classes respected); warnings for `if (A = B)`, a `;` right after if/for/while, `X = X;`, and a `UE_LOG`/`FString::Printf` format whose `%` count differs from the arguments. Results appear as squiggles in their own colours (red errors, yellow warnings, blue suggestions; Fonts and Colors → "UnrealSense - Error/Warning/Suggestion"), light bulbs and Error List entries (suggestions stay out of it). |
| **False IntelliSense errors hidden** | Visual Studio's IntelliSense reports errors that are not real in Unreal code; UnrealSense hides them from the squiggles and the Error List with general rules: when IntelliSense could not configure a file (it cannot open an `#include` of a header that exists, e.g. `E1696` on `"CoreMinimal.h"`), every error of that file is a consequence and is hidden, except real missing includes; when the `.generated.h` is missing or stale (UHT runs at the next build), the errors on reflection macros (`UCLASS`, `UPROPERTY`, `GENERATED_BODY`...), on `Super`/`ThisClass`/`StaticClass` and on `Name_Implementation`/`Name_Validate`/`Execute_Name` of a matching UFUNCTION are hidden. Real errors stay. Option *IntelliSense errors in Unreal files*: `HideFalse` (default), `HideAll` (no IntelliSense error: UnrealSense's inspections and build errors stay), `ShowAll`. |
| **Navigation** | **Go to definition** with `Ctrl+click` (or `Alt+click`/`Ctrl+Alt+click` when that modifier is chosen in Tools › Options › Text Editor › General › *Enable mouse click to perform Go to Definition*), `F12` or `Alt+G` (own C++ index): a function call goes to its implementation, an implementation to its declaration and back, a variable (member, global, local, parameter) to its declaration, a type to its definition, also in unsaved code; a BlueprintNativeEvent/RPC goes to `_Implementation`/`_Validate` and back to the UFUNCTION. When the index knows nothing at the click, Visual Studio's own Go To Definition runs (option *Go to definition (Ctrl+click, F12)*). `Alt+O` (**Switch Header/Source**, also in the editor's context menu) opens the `.cpp` of a header or the header of a `.cpp`, following the module's `Public`/`Classes` ⇄ `Private` layout, for engine and plugin files too; `Alt+G` does the same when the caret is not on a reflected symbol. The **Unreal Explorer** window lists modules (`.Build.cs`, dependencies, reflected types), plugins, Blueprints grouped by C++ parent, and config files, with a search box. |
| **Class hierarchy** | With the caret on a class or struct name, *Class Hierarchy...* in the Quick Menu (`Alt+Shift+Q`, or Extensions › UnrealSense) opens a drop-down at the mouse pointer (the class name is boxed in amber in the editor while it is open; the same for *Base and Overrides*) with the class, its base classes (nearest first, indented: `ACharacter`, `APawn`, `AActor`, `UObject`..., interfaces included) and its derived classes as a tree with guide lines and, next to each class, how many subclasses it has. Classes with subclasses collapse and expand (click the arrow, or Left/Right; Ctrl+Left/Right for all); with more than 40 derived classes only the direct subclasses start expanded. Click one (or Up/Down and Enter) to open its file at the class; type to filter (matches keep their parent classes, for context). Engine and plugin classes come from the own C++ index; without it (still building, or off) the project's UCLASS/USTRUCT types are listed. Classes deriving from very common bases (`UObject`) are listed up to 2,000. |
| **Base and overrides** | With the caret on a virtual function, an override or a `UFUNCTION` Blueprint event, the Quick Menu shows *Base and Overrides of X...* in place of *Class Hierarchy...*: the function, the functions it overrides up to where it is first declared (marked *origin*), and its overrides in the subclasses as a tree. A `BlueprintNativeEvent` is followed through its `_Implementation` overrides, and on a `BlueprintNativeEvent` or `BlueprintImplementableEvent` (*Blueprint Implementations of X...*) the Blueprints implementing it are listed too: click one to open it in the Unreal Editor. Needs the own C++ index. |
| **Override virtual functions** | `Alt+Shift+V` (or the light bulb on a class name, or the editor context menu) lists the virtual functions the class at the caret inherits from its engine, plugin and project bases and from implemented interfaces, grouped by declaring class, with a filter. Only the functions you check are added: `virtual ... override;` in the class (under the parent's access, inside the same `#if WITH_EDITOR` blocks) and, optionally, definitions calling `Super::` at the end of the `.cpp`. BlueprintNativeEvents and RPCs are offered as their `_Implementation`; final, deprecated and already overridden functions are left out. |
| **Create implementation** | `Alt+Shift+D` (or the light bulb on a declaration with no definition yet) writes the `.cpp` body of the function declared at the caret in a header (select several declarations to do them all). Unreal's names are used: a BlueprintNativeEvent or a `Server`/`Client`/`NetMulticast` RPC becomes `Name_Implementation`, `WithValidation` adds `bool Name_Validate(...)` returning `true`; a BlueprintImplementableEvent, a pure virtual or an interface event gets none. An override calls the parent version (`Super::Name(...)`, or `return Super::Name(...)`) when an ancestor really implements it (not for interface or pure functions); a constructor taking `const FObjectInitializer&` gets `: Super(ObjectInitializer)`. The definition goes next to the definitions of the neighbouring declarations, inside the same `#if`, and the caret lands in its body; if it already exists, the caret goes there. |
| **Add #include / forward declaration** | With the caret on a name, *Add #include* in the Quick Menu (`Alt+Shift+Q`, or Extensions › UnrealSense) adds the `#include` of its header, written as Unreal code writes it (`"GameFramework/Actor.h"`): for a class, struct or enum its own header; for a variable or function the header declaring it when the file does not see it yet, otherwise the header of its type (`TObjectPtr<UMyComponent> Comp` → `UMyComponent`'s header, `GetWorld()` → `UWorld`'s). The line goes after the other includes, before the `.generated.h` one. In a header, *Add Forward Declaration* also appears: it writes `class UMyComponent;` (`struct`, `enum class EMode : uint8;`, inside its namespace if it has one) after the includes or next to the header's other forward declarations. Templates, nested classes and enums without an underlying type cannot be forward-declared: the status bar says so. Needs the own C++ index. |
| **Declare delegate** | *Declare Delegate...* (Quick Menu `Alt+Shift+Q`, or Extensions › UnrealSense) opens a panel to build a delegate: kind (Single, Multicast, Dynamic, Dynamic Multicast, Sparse, Event), name, type (`F<Name>Signature` by default), return type (only where Unreal allows it) and up to nine parameters, with a live preview. **Create** writes the right `DECLARE_..._DELEGATE` macro after the `#include`s, just above the class at the caret, and the member at the caret (`UPROPERTY(BlueprintAssignable)` for dynamic multicast and sparse delegates; for an Event, the macro, a public accessor and private storage inside the class), optionally with the handler's signature (`UFUNCTION()` for dynamic delegates); one undo removes it all. **Copy** puts the same text on the clipboard. Under the preview, a short note says what the chosen kind is for, and *Usage example* expands into how to bind, call and unbind it, written with your delegate's names. Errors Unreal would report (parameter names missing on a dynamic delegate, a comma in a type, a return value on a multicast) are shown before writing. |
| **New Unreal Class** | **Unreal Class...** (Solution Explorer › Add on a project or folder, Extensions › UnrealSense, or the Unreal Explorer's **New class** button) opens a dialog: class name, parent from **Common** (Actor, Character, Actor Component, Interface, Struct, Enum, Empty, subsystems, User Widget...) or **All Classes** (project, project plugins, engine and the engine plugins the project enables, read in the background and cached), base folder Root/Public/Private and path. The path can be in any module (a folder with a `.Build.cs`, or below one): the project, its plugins, the engine or an engine plugin. It starts at the folder of the file open in the editor (or of the folder selected in Solution Explorer), and the **...** button opens UnrealSense's own folder picker: the source folders of the project, its plugins and the engine as a tree with modules and plugins marked, or the modules matching a search. It writes the `.h` (in `Public`) and `.cpp` (in `Private`) like the Unreal Editor: prefixed name (`A`/`U`/`F`/`E`, `UMyX`+`IMyX` for interfaces), `<MODULE>_API`, `CoreMinimal.h`, the parent's header and the `.generated.h`, with the engine's own templates (constructor, `BeginPlay`, `Tick`, `SetupPlayerInputComponent`, `TickComponent`, subsystem `Initialize`/`Deinitialize`...). Structs and enums are header only. If the module's `.Build.cs` does not depend on the parent's module (e.g. `UMG`, `DeveloperSettings`), it offers to add it. The files are added to the game's `.vcxproj` under the matching filter and opened (files of engine modules and engine plugins are only opened: adding them to `UE5.vcxproj`, ~120,000 items, blocks Visual Studio for seconds per file, and **Generate Project Files** adds them); IntelliSense resolves their includes after the next **Generate Project Files** (UBT's Makefile projects cannot give a new file its module's include paths without reloading the project). |
| **Member completion** | After `.` and `->` it lists the functions and variables of the expression's class, its bases included (engine ones too), as you type: locals, parameters, `this`, call results such as `GetOwner()->`, members, template instances. Private and protected members are always listed, with a lock where they are not accessible (classes and functions declared `friend` count as having access). A `.` typed after a raw pointer becomes `->` by itself; after a smart pointer (`TObjectPtr`, `TWeakObjectPtr`, `TSharedPtr`, `TUniquePtr`...) the `.` stays, the list shows the wrapper's members (`Get`, `IsValid`, `Reset`) and the pointed object's ones, and choosing one of the latter writes `->`. The type comes from the own C++ index (below), which reads the editor's text as it is, unsaved edits included. Works in engine and plugin files too (also `AdditionalPluginDirectories`): when such a file is opened it is added to the index with its headers (one quick incremental build). Option: Code completion › Member completion after . and ->. |
| **Name completion** | Wherever you type a name, in `.cpp` and `.h` files alike (function bodies, class bodies, file and namespace scope, parameters, template arguments `TArray<TS`, base lists `: public AAc`, constructor initializers, default member values, arguments of `DECLARE_*` delegate macros and `UE_LOG`), the list shows, in this order: the function's parameters and locals; the members of the class and of its bases (same access rules; only the static ones in a static function), nested types included; the values of the enum expected there (`case `, `State = `, `State == `, an argument whose parameter is an enum as in `Name.Find(TEXT("x"), ` → `ESearchCase::IgnoreCase`; written `EMyState::Value`); types, functions, variables and namespaces (`TSoftObjectPtr`, `AActor`, `LogLyra`...) from the enclosing namespaces, `using namespace` and the global namespace; macros (`UE_LOG`, `DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam`, `GENERATED_BODY`... with their parameters); keywords. After `::` the names inside that scope: `UE::Math::`, `EMyEnum::` (enumerators), `Super::`/`AMyBase::` (members and nested types), and in a `.cpp` at namespace level `void AMyActor::` lists all the class's own functions, for out-of-line definitions. After `class `/`struct ` (forward declarations) class names are suggested without being preselected. Inside `#include "` the folders and headers of the include folders. Types declared in the file and not saved yet (a delegate declared a line above) are listed too. On a dynamic delegate, `.` also lists `AddDynamic`, `AddUniqueDynamic`, `RemoveDynamic`, `IsAlreadyBound`/`BindDynamic`. **Missing includes**: choosing a type, function or variable whose header the file does not see (directly or through other includes) adds its `#include` (after the last one, before the `.generated.h`), written as Unreal code does: relative to the module's `Public`/`Classes`/`Private` folder (`"GameFramework/Actor.h"`), or from the file's folder; an absolute path only when no include folder holds the header. One undo removes both. **No waiting for IntelliSense**: where UnrealSense lists names, Visual Studio's C++ list is not asked, so the list shows as soon as the own index answers (IntelliSense can take seconds after editing a header, or with many projects loaded); where the own index has nothing, Visual Studio's list opens instead. Options: Code completion › Name completion, Add missing #include, Don't wait for Visual Studio's C++ list. |
| **Colorization** | UnrealSense colours C++ files of the project itself, every token included, so the result is the same with or without other extensions or IntelliSense's semantic colours. Lexical, as you type: keywords (`int32`/`uint8`... too), comments and doc comments (`///`, `/** */`), strings (with `#include <...>` paths), numbers, directives, punctuation; reflection macros (`UCLASS`, `UPROPERTY`, `GENERATED_BODY`...) in bold, their specifiers, `meta=(...)` keys (italic) and values. Semantic, from the own C++ index on the text being edited: UObject types (deriving from `UObject`, so `A`/`U` classes) apart from value types (`FVector`, `TArray`), interfaces, enums and enumerators, typedefs and template parameters, namespaces, functions (static in italic), fields (static in italic), globals, locals, parameters and macros; until the index answers, identifiers are guessed from the Unreal prefixes and the next token. Members exposed to Blueprints (BlueprintCallable, BlueprintReadWrite...) are bold. Colours: Tools › Options › Environment › Fonts and Colors, items `UnrealSense - ...` (defaults for dark and light themes, picked from the theme when Visual Studio starts). Options: Colorization › UnrealSense colorization, Semantic colours from the own index. Turning off Text Editor › C/C++ › Advanced › *Disable Semantic Colorization* saves IntelliSense that work. |
| **Build.cs** | Completes module names inside string literals of `*.Build.cs`/`*.Target.cs` (project, engine and plugin modules). |

Commands (Extensions › UnrealSense, and the editor's context menu): **Go to Symbol...** (`Alt+Shift+T`: types, functions,
fields, enum values, macros, delegates of the project, its plugins and the engine headers, fuzzy: `GAL` finds `GetActorLocation`,
`AFoo::Bar` filters by container; `Ctrl+1/2/3/4` or Tab switch Symbols/Types/Files/In File, In File being the active
document), **Go to Symbol in File...** (`Alt+M` or `Alt+Shift+M`, opens on the In File tab:
the current file's declarations plus the locals and parameters inside its functions, with their type and function; an empty
query lists the whole file starting at the caret, `Tick::` the locals of `Tick`; locals need the own index), **Go to File...** (`Ctrl+Shift+T`, `file.cpp:120`
opens at a line; option *Include engine symbols and files*). In every search box (Go to, Unreal Explorer, class hierarchy, Quick Menu,
override, module and parent class lists) words separated by spaces match independently: `shooter char` finds what contains either word
and ranks what contains both first. The *Fuzzy* checkbox of the Go to popup (`Ctrl+F`, option *Fuzzy search*, on by default) also
matches subsequences like `GAL` or `shchar` and typos like `charcter`; off, each word must appear as typed, **Find Blueprint Usages**, **GoTo Implementation/
Declaration**, **Unreal Explorer**, **Unreal Class...**, **Rebuild UnrealSense Index** (re-reads headers and assets). **Restore Visual
Studio Indexing** appears only if an earlier version turned Visual Studio's own C++ database off. **Quick Menu** (`Alt+Shift+Q`) opens
all of these in one popup at the mouse pointer (commands still act on the caret, whose word is shown at the top: *At caret: AMyActor*), grouped into search, code, project and tools, with
each command's shortcut and a search box: type to filter, Up/Down and Enter to run.

**Look**: UnrealSense's windows and dialogs (Unreal Explorer, Find Usages, Blueprint Usages, Go to Symbol/File, Quick Menu, New
Unreal Class, Override Virtual Functions) have two themes, chosen in Tools › Options › UnrealSense › General › **UI theme**:
- **Unreal** (default): the style of the Unreal Editor 5: dark panels, recessed lists with blue selection, rounded search boxes,
  Unreal-style title bar. The same in every Visual Studio theme.
- **Classic**: Visual Studio's own colours, font and title bars, with rounded buttons in Visual Studio's button colours. It follows
  the Visual Studio colour theme (Dark, Light, Blue or a custom theme) as soon as it changes.

Open windows switch theme when the options are saved.

Options: Tools › Options › UnrealSense (in Visual Studio 2026 a page of the new settings view, *All Settings › UnrealSense*,
with the values saved before; Visual Studio 2022 keeps the classic page). Log: Output › UnrealSense and one file per Visual Studio session in
`%LOCALAPPDATA%\UnrealSense\Logs` (`UnrealSense_<date>_<time>_pid<id>.log`; the newest five are kept, a session's file stops
at 20 MB).
When the project loads, the log shows a `Blueprint index:` summary (assets read, references per C++ module, detected
module aliases): check it first when a counter looks wrong.

**Which project is loaded**: one Unreal project at a time, the one of the opened solution (or folder). In an engine-root
solution with several games, the option *Unreal project* chooses (when it is one of the solution's games), then the
startup project. Files of another project, e.g. a second checkout of the same game in another Perforce stream or branch,
do not replace it: UnrealSense features are off in them and the log says so once. A project in a folder listed by an engine
tree's `*.uprojectdirs` uses that engine, whatever its `EngineAssociation` says.

**Hangs**: when Visual Studio stops responding for more than a second, the session's
`%LOCALAPPDATA%\UnrealSense\Logs\Hangs_<date>_<time>_pid<id>.log` (same session name as the main log, newest five kept) says
whether UnrealSense code was running on the UI thread (and which operation), which UnrealSense locks were held or awaited
and by whom, and any wait cycle (deadlock) between UnrealSense threads, ending with a verdict ("not UnrealSense code" when
the UI thread was blocked elsewhere). A hang that lasts is written at 5, 15, 60 and 300 seconds, so a Visual Studio that
has to be killed still leaves its record; each of these reports also has the UI thread's managed call stack, so a hang in
Visual Studio itself or in another extension shows where it is stuck. UnrealSense operations that take 300 ms or more on the UI thread are listed as
`slow UI operation`. When the whole Visual Studio process stops (every thread, not only the UI one: a blocking garbage
collection, paging, the process suspended from outside) the file says `WHOLE PROCESS STALLED` with the process and machine
memory; every hang report carries the memory too, and a `memory:` line is written each time the process grows or shrinks by
a gigabyte. Option: Diagnostics › Log Visual Studio hangs.

### Own C++ index (on by default)

**Own C++ index** (`Use the own C++ index` in the options, category "Find Usages (own index)"):
member completion and name completion (above) and Find Usages from UnrealSense's own C++ indexer, written from scratch (no compiler). It runs as a separate process
(`OwnIndexer\usindex.exe`, shipped in the VSIX with its own .NET runtime), indexes the project and the engine headers it
includes in a few seconds, keeps the index on disk and updates it incrementally after C++ files are saved (only the changed
files are read again; when the saved files declare nothing new, the previous symbol table is reused: Lyra with the whole
engine about 1 s, about 4 s when a declaration changed), and also while you type in a header: a member added to a `.h` is known to completion and go to
definition in its `.cpp` before the header is saved (a completion asked right after waits for that update, at most 4 seconds). It reads each file's include paths and definitions from UnrealBuildTool's compile database, which
UnrealSense generates on the first start and again when the build rules change or a source file is added (about a minute).
Turning the option off also turns both completions off. With the option on, **Find Usages** appears in the editor's context menu and under Extensions › UnrealSense. It also lists uses
inside macros: in macro arguments (`UE_LOG`, `check`, `AddDynamic`...), in the body of a project `#define` (resolved where the macro is
expanded) and in `UPROPERTY(ReplicatedUsing = OnRep_X)` / `BlueprintGetter` / `BlueprintSetter`. Names that macros build
from their arguments are known too: the `NAME_None`/`NAME_*` constants, the accessors of `ATTRIBUTE_ACCESSORS(UMyAttributeSet, Health)`
(`GetHealth`, `SetHealth`, `InitHealth`, `GetHealthAttribute`: go to definition leads to the macro line), stat and Slate argument
macros; the verbosity of `UE_LOG` (`Warning`, `Log`...) is the `ELogVerbosity` value. Unreal's old-style enums
(`namespace ESearchCase { enum Type {...} }`) are coloured and listed as enums.
`Index the whole engine` (on by default) also indexes every engine and plugin source file (about 100k files); turn it off to
index only the engine headers the project includes. Between builds the process
gives back the memory a build used: what stays is the index and what completion needs (Lyra, project index: about 0.3 GB;
whole engine: 2.4 GB of managed heap, about 3.5 GB in Task Manager; more with a larger engine); each build logs
`memory after the build: managed heap …, working set …`, and the save once the editor is idle logs `memory after the save:`. Log lines start with
`OwnIndex:`. Uses on an object whose type the indexer cannot infer are listed apart, under "Uncertain" at the bottom of the
results, instead of being guessed. The code lines in the results are coloured with the editor's colours (Tools › Options ›
Fonts and Colors: keywords, strings, comments, macros, Unreal types, calls, members), the searched name in bold.

## Installing and updating

Download `UnrealSense-<version>.vsix` and `Install-UnrealSense.ps1` from the
[GitHub releases](https://github.com/AssoAndrea/Unreal-Sense/releases). Run the script (it picks the highest version
next to it and installs it into the newest Visual Studio), or double-click the `.vsix`; to update, install the new one
over the old.

**Automatic updates**: add `https://assoandrea.github.io/Unreal-Sense/gallery/atom.xml` under Tools › Options ›
Environment › Extensions › Additional Extension Galleries. Visual Studio then finds every new release by itself and
installs it when it closes (Extensions › Manage Extensions › Updates shows it earlier).

Italian guide: [GUIDA](https://assoandrea.github.io/Unreal-Sense/GUIDA.html). Bugs and requests:
[issues](https://github.com/AssoAndrea/Unreal-Sense/issues).

## License

UnrealSense is free to use. Its license agreement ([LICENSE.txt](LICENSE.txt), shown when you install it) lets the
author require a paid license key in the future, also for copies already installed. To know whether one is needed, the
extension downloads a small signed public file (`license-policy.json` on this repository's GitHub Pages) about every
12 hours; the request carries nothing about you, your PC or your projects. Without network access it keeps working.
If a key ever becomes required, an info bar in Visual Studio says so and how many days are left, and
**Extensions › UnrealSense › License...** is where the key goes. The same file can ask a version with a security problem
to be updated: the info bar then links the new release, and after the announced date that version's features stay off
until it is updated. Log lines start with `License:`.
