UnrealSense — guida rapida

Un aiuto per i progetti Unreal in Visual Studio 2022 e 2026: ti dice dove le tue classi C++ sono usate nei Blueprint, suggerisce gli specifier di UPROPERTY/UFUNCTION e segnala gli errori tipici di Unreal mentre scrivi. Funziona anche con l'editor di Unreal chiuso.

Installare e aggiornare

  1. Chiudi Visual Studio.
  2. Scarica UnrealSense-<versione>.vsix dalle release e fai doppio clic sul file.
  3. Spunta le versioni di Visual Studio in cui la vuoi (2022, 2026) e premi Install.

Per aggiornare si fa la stessa cosa con il file nuovo, senza disinstallare. Se nell'elenco non compare la tua versione di Visual Studio, metti Install-UnrealSense.ps1 accanto al .vsix e fai clic destro sullo script › Esegui con PowerShell.

Aggiornamenti automatici: in Visual Studio apri Tools › Options › Environment › Extensions, in Additional Extension Galleries premi Add, scrivi un nome (UnrealSense) e come URL https://assoandrea.github.io/Unreal-Sense/gallery/atom.xml, poi Apply. Da quel momento Visual Studio trova da solo le versioni nuove e le installa quando lo chiudi.

Licenza

UnrealSense è gratuita. La licenza (LICENSE.txt, la vedi quando la installi) permette all'autore di chiedere in futuro una chiave di licenza a pagamento, anche per le copie già installate.

Per saperlo, circa ogni 12 ore l'estensione scarica un piccolo file pubblico firmato (license-policy.json sulle GitHub Pages del progetto): la richiesta non contiene niente su di te, sul PC o sui tuoi progetti. Senza rete continua a funzionare. Se un giorno servirà una chiave, una barra in Visual Studio te lo dirà con i giorni che restano, e la chiave si inserisce in Extensions › UnrealSense › License.... Lo stesso file può chiedere di aggiornare una versione con un problema di sicurezza: la barra ti porta alla versione nuova e, dopo la data indicata, quella versione resta spenta finché non la aggiorni.

Primo avvio

Apri la soluzione del progetto come fai di solito. UnrealSense riconosce il progetto da solo e in pochi secondi legge le classi C++ e i Blueprint (la prima volta può volerci un po' di più). Da lì in poi funziona tutto in automatico.

Cosa trovi nel codice

Quanti Blueprint usano una classe

Accanto a classi, funzioni e proprietà esposte ai Blueprint compare una scritta grigia. Cliccala per vedere l'elenco dei Blueprint.

UCLASS()
class AMyCharacter : public ACharacter12 derived Blueprints
{
UFUNCTION(BlueprintCallable)
void Jump();3 Blueprint usages

Il conteggio include anche i Blueprint che derivano da altri Blueprint o da classi C++ figlie (indicati con "via …").

Cercare gli usi nei Blueprint

Metti il cursore sul nome di una classe, funzione o proprietà e premi Alt+Shift+B (oppure clic destro › Find Blueprint Usages). Si apre la finestra Blueprint Usages: doppio clic su una riga per mostrare il file dell'asset in Esplora file.

Cercare un testo dentro i Blueprint

Extensions › UnrealSense › Search Text in Blueprints... (o dal Quick Menu) apre la finestra Search in Blueprints: scrivi un testo qualsiasi e vengono elencati tutti i Blueprint e gli asset di dati che lo contengono, non solo i riferimenti. Per ogni risultato vedi cosa è e dove si trova: commento di un riquadro o di un nodo, valore scritto in un pin (EventGraph › Call PrintString › pin In String), default o tooltip di una variabile, testo di un widget, riga di una DataTable, voce di una String Table, proprietà di un Data Asset; con Names anche nomi di variabili, funzioni, pin e gameplay tag.

Doppio clic apre l'asset nell'Unreal Editor. Opzioni: Match case, Whole word, All assets (anche texture, mesh, suoni, animazioni) ed Editor caches (testi che l'editor rigenera da solo, nascosti di default). Gli asset sono letti dal disco, anche a editor chiuso: su Lyra meno di un secondo.

Informazioni al passaggio del mouse

Passa il mouse su uno specifier (es. BlueprintReadWrite) per leggerne la spiegazione, o sul nome di una classe, funzione o proprietà per vedere dove è usata nei Blueprint.

Suggerimenti mentre scrivi

Dentro UPROPERTY(...), UFUNCTION(...), UCLASS(...) ecc. Visual Studio propone gli specifier validi per la tua versione di Unreal, con la spiegazione. Funziona anche per i valori, per esempio le Category già usate nel progetto o la funzione da usare in ReplicatedUsing.

Completamento dei membri (. e ->)

Scrivi il nome di una variabile e un punto: Visual Studio elenca le funzioni e le variabili della sua classe (comprese quelle delle classi base dell'engine), e la lista si restringe mentre scrivi. Funziona su variabili locali, parametri, this, risultati di chiamate (GetOwner()->) e membri; i membri privati e protetti compaiono sempre, con un lucchetto accanto dove non sono accessibili (le classi e le funzioni dichiarate friend li vedono come accessibili). Se la variabile è un puntatore il punto diventa da solo ->. Con TObjectPtr, TWeakObjectPtr, TSharedPtr... il punto resta: la lista mostra sia le funzioni del puntatore (Get, IsValid) sia quelle dell'oggetto puntato, e scegliendo una di queste il punto diventa ->. Funziona anche nei file dell'engine e dei plugin (vengono aggiunti all'indice quando li apri).

Completamento dei nomi (locali, membri, tipi, macro)

Ovunque inizi a scrivere un nome, nei .cpp e nei .h (corpo di funzione o di classe, livello di file, parametri, argomenti template come TArray<TS, basi : public AAc, initializer del costruttore, argomenti delle macro DECLARE_* e di UE_LOG), Visual Studio elenca nell'ordine: parametri e variabili locali; membri e tipi annidati della classe e delle sue basi (stesse regole di accesso, solo statici in una funzione static); i valori dell'enum atteso dopo case , Stato = , Stato == e negli argomenti di una funzione che vuole un enum (Nome.Find(TEXT("x"), propone ESearchCase::IgnoreCase); tipi, funzioni, variabili e namespace (TSoftObjectPtr, AActor, LogLyra, NAME_None, enum dell'engine come ESearchCase..., anche quelli del file non ancora salvati e quelli creati dalle macro, come GetHealth/SetHealth di ATTRIBUTE_ACCESSORS); le macro con i parametri (UE_LOG, DECLARE_DYNAMIC_MULTICAST_DELEGATE_OneParam...); le parole chiave. Un membro appena aggiunto in un .h compare nel .cpp subito, anche prima di salvare l'header.

Dopo :: elenca i nomi dello scope: UE::Math::, EMioEnum::, Super::; in un .cpp fuori dalle funzioni void AMioActor:: elenca le funzioni della classe da definire. Dopo class /struct propone i nomi di classe senza selezionarne nessuno. Dentro #include " propone cartelle e header. Su un delegate dinamico il punto elenca anche AddDynamic, RemoveDynamic, IsAlreadyBound (o BindDynamic).

Include automatici: scegliendo un nome il cui header il file non vede, UnrealSense aggiunge l'#include dopo l'ultimo (prima del .generated.h), relativo alla cartella Public/Classes/Private del modulo ("GameFramework/Actor.h") o alla cartella del file; assoluto solo se nessuna cartella di include lo contiene. Un solo Ctrl+Z toglie nome e include. La lista non si apre mentre dichiari qualcosa (FVector Posizione), nei commenti e nelle stringhe; Ctrl+Spazio la apre comunque.

Avvisi e correzioni rapide

Gli errori tipici di Unreal vengono sottolineati prima di compilare: include .generated.h mancante o sbagliato, GENERATED_BODY() mancante, prefissi A/U/F/E/I sbagliati, _Implementation mancante, puntatori a UObject senza UPROPERTY né smart pointer (il garbage collector non li vede) e altri. Anche errori C++ generici, solo dove i tipi sono certi: scrittura su una variabile, un membro o un oggetto const (anche dentro un metodo const), chiamata di un metodo non const su un oggetto const, membro che non esiste, numero di argomenti sbagliato, membro private/protected usato dove non è accessibile (friend, classi derivate e annidate rispettate); e avvisi per if (A = B), ; subito dopo if/for/while, X = X; e UE_LOG/FString::Printf con un numero di % diverso dagli argomenti. Quando compare la lampadina puoi applicare la correzione con un clic (per esempio crea il corpo di _Implementation nel .cpp, o aggiunge UPROPERTY() con TObjectPtr). Gli errori sono sottolineati in rosso, gli avvisi in giallo e i suggerimenti in blu (colori in Strumenti › Opzioni › Tipi di carattere e colori, voci "UnrealSense - ..."). Errori e avvisi sono anche nell'Elenco errori.

IntelliSense di Visual Studio, invece, segnala in Unreal molti errori che non esistono. UnrealSense li nasconde (sottolineature ed Elenco errori) quando li riconosce come falsi:

  • IntelliSense non è riuscito a configurare il file: non apre un #include di un header che esiste (per esempio E1696 su "CoreMinimal.h") e poi sottolinea tutto il file (UCLASS, UPROPERTY, DECLARE_...). Restano solo gli include che mancano davvero.
  • Il .generated.h manca o è vecchio (UHT lo rifà alla prossima build): errori sulle macro di riflessione, su Super, ThisClass, StaticClass, e su Nome_Implementation, Nome_Validate, Execute_Nome quando l'header dichiara l'UFUNCTION giusto.

Gli errori veri restano. L'opzione IntelliSense errors in Unreal files sceglie: HideFalse (default), HideAll (nessun errore di IntelliSense: restano gli avvisi di UnrealSense e gli errori di compilazione) o ShowAll.

Andare alla definizione

Ctrl+clic su un nome (o il tasto scelto in Tools › Options › Text Editor › General › "Enable mouse click to perform Go to Definition", per esempio Alt; oppure F12, o Alt+G): dalla chiamata di una funzione alla sua implementazione, dall'implementazione alla dichiarazione e ritorno, da una variabile (membro, globale, locale, parametro) alla sua dichiarazione, da un tipo alla definizione della classe. Funziona anche sul codice non salvato. Per le UFUNCTION BlueprintNativeEvent e RPC porta a _Implementation o _Validate, anche dalla chiamata, e ritorno; sui nomi creati da una macro (NAME_None, GetHealth) porta alla riga della macro. Se l'indice di UnrealSense non sa niente in quel punto parte il Go To Definition di Visual Studio; con Alt+G fuori da un nome noto passa al file corrispondente (come Alt+O).

Colori del codice

UnrealSense colora da sé i file C++ del progetto, senza dipendere da IntelliSense o da Visual Assist.

Mentre scrivi colora keyword (anche int32), commenti e commenti di documentazione, stringhe, numeri e direttive. Le macro di reflection (UCLASS, UPROPERTY, GENERATED_BODY…) sono in grassetto, con i loro specifier, le chiavi di meta=(…) e i valori.

Dall'indice C++ di UnrealSense, anche sul codice non salvato, arrivano i colori dei nomi:

  • i tipi UObject (A…/U…), distinti dai tipi valore (FVector);
  • interfacce, enum e loro valori (anche gli enum "vecchio stile" come ESearchCase e la verbosità di UE_LOG), typedef, namespace;
  • funzioni, campi, globali, locali e parametri (quelli statici in corsivo);
  • le macro.

I membri esposti ai Blueprint sono in grassetto.

Per cambiare i colori: Tools › Options › Environment › Fonts and Colors, voci UnrealSense - ….

Cercare un simbolo o un file

Alt+Shift+T (Go to Symbol...) cerca classi, funzioni, variabili, valori di enum, macro e delegate del progetto, dei plugin e degli header dell'engine: bastano le iniziali (GAL trova GetActorLocation) o AFoo::Bar per cercare dentro una classe. Ctrl+Shift+T (Go to File...) fa lo stesso con i file; File.cpp:120 apre alla riga 120. Ctrl+1/2/3/4 (o Tab) passano fra Symbols, Types, Files e In File (i simboli del file aperto), Invio apre, Esc chiude.

In tutte le caselle di ricerca (Go to, Unreal Explorer, gerarchia delle classi, Quick Menu, override, liste di moduli e classi padre) le parole separate da spazio sono cercate ognuna per conto suo: shooter char trova ciò che contiene almeno una delle due, prima ciò che le contiene entrambe. La casella Fuzzy della finestra Go to (Ctrl+F, opzione Fuzzy search, attiva di default) accetta anche le lettere sparse (GAL, shchar) e gli errori di battitura (charcter); spenta, ogni parola deve comparire così com'è scritta.

Alt+M o Alt+Shift+M (Go to Symbol in File...) apre la stessa finestra sulla tab In File e cerca solo nel file aperto, comprese le variabili locali e i parametri dentro le funzioni (con tipo e funzione). Senza testo mostra tutto il file in ordine, partendo dal cursore; Tick:: mostra solo i locali di Tick.

Tutti i comandi in un menu

Premi Alt+Shift+Q (o Extensions › UnrealSense › Quick Menu): dove si trova il mouse si apre un menu con tutti i comandi di UnrealSense, divisi in ricerca, codice, progetto e strumenti, ognuno con la sua scorciatoia. I comandi agiscono comunque sul cursore di testo: in cima, in piccolo, il menu scrive il nome su cui si trova (At caret: ...). Scrivi per filtrare, scegli con le frecce e premi Invio; Esc chiude. Il menu mostra solo i comandi che hanno senso dove si trova il cursore: per esempio Declare Delegate... solo in un header, fuori dai corpi delle funzioni, dai commenti e dalle stringhe; Create Implementation solo su una dichiarazione che non ha ancora il corpo; GoTo Implementation/Declaration solo sul nome di una funzione. Le scorciatoie e il menu Extensions › UnrealSense funzionano ovunque e, nel posto sbagliato, la barra di stato spiega perché.

Le finestre di UnrealSense (Unreal Explorer, Find Usages, Blueprint Usages, Go to Symbol/File, Quick Menu e i dialoghi New Unreal Class, Override e Declare Delegate) hanno due temi, da Tools › Options › UnrealSense › General › UI theme: Unreal (di default, lo stile dell'editor di Unreal Engine 5, uguale con ogni tema di Visual Studio) o Classic (i colori, il font e le barre del titolo di Visual Studio, che seguono subito il tema scuro, chiaro, blu o personalizzato). Le finestre aperte cambiano tema quando salvi le opzioni.

Dal .h al .cpp e viceversa

Premi Alt+O (o clic destro › Switch Header/Source) per aprire il .cpp dell'header che stai guardando, o l'header del .cpp. Segue la struttura dei moduli Unreal (Public\Ui\Menu.h ⇄ Private\Ui\Menu.cpp, anche Classes) e funziona anche nei file dell'engine e dei plugin.

Override delle funzioni virtuali

Con il cursore dentro una classe (nel .h, o in una sua funzione nel .cpp) premi Alt+Shift+V (o clic destro › Override Virtual Functions...): si apre l'elenco delle funzioni virtuali ereditate (engine, plugin, progetto, interfacce). Spunta quelle che vuoi: UnrealSense aggiunge le dichiarazioni nel .h e, se lo lasci spuntato, le definizioni che chiamano Super:: nel .cpp. Le classi dell'engine si caricano in background quando apri il progetto; se premi il tasto subito dopo, la barra di stato dice che le sta caricando.

Creare l'implementazione di una funzione (Create Implementation)

Scrivi la dichiarazione nel .h, lascia il cursore sulla riga (anche su quella dell'UFUNCTION(...)) e premi Alt+Shift+D, oppure Ctrl+. › Create implementation of ... (la lampadina compare solo se la definizione non esiste ancora). UnrealSense scrive il corpo nel .cpp vicino alle definizioni delle funzioni vicine, dentro lo stesso #if, e ci porta il cursore. Selezionando più dichiarazioni le crea tutte.

  • BlueprintNativeEvent e le RPC Server/Client/NetMulticast diventano Nome_Implementation; con WithValidation anche bool Nome_Validate(...) che restituisce true.
  • Un override chiama la versione del padre (Super::Nome(...), con return se restituisce un valore) solo se un antenato la implementa davvero (non per interfacce o funzioni pure).
  • Un costruttore con const FObjectInitializer& riceve : Super(ObjectInitializer).
  • BlueprintImplementableEvent, funzioni pure, inline e gli eventi delle interfacce non hanno definizione: la barra di stato spiega perché. Se la definizione c'è già, il cursore va lì.

Dichiarare un delegato

Metti il cursore nell'header, dove vuoi il membro (di solito una riga vuota nella sezione public:), e apri Alt+Shift+Q › Declare Delegate... (o Extensions › UnrealSense › Declare Delegate...). Nel pannello scegli:

  • il tipo: Single, Multicast, Dynamic, Dynamic Multicast, Sparse o Event (Sparse ed Event solo con il cursore dentro la classe che li possiede);
  • il nome (OnScoreChanged) e il tipo del delegato, che segue il nome (FOnScoreChangedSignature) finché non lo cambi;
  • il tipo di ritorno, solo per Single e Dynamic;
  • fino a nove parametri (per i delegati dinamici il nome è obbligatorio);
  • se dichiarare anche il membro e la firma dell'handler.

L'anteprima mostra il codice mentre scrivi e avvisa degli errori che darebbe Unreal (per esempio una virgola in un tipo come TMap<int32, FString>). Create scrive la macro DECLARE_..._DELEGATE... giusta dopo gli #include, sopra la classe, e il membro al cursore (UPROPERTY(BlueprintAssignable) per dynamic multicast e sparse; per un Event macro, accessor pubblico e campo privato dentro la classe); un solo Ctrl+Z annulla tutto. Copy copia lo stesso codice negli appunti. Sotto l'anteprima una nota spiega a cosa serve il tipo scelto, e Usage example si espande con un esempio di come collegarlo, chiamarlo e scollegarlo, scritto con i nomi del tuo delegato.

Gerarchia di una classe

Con il cursore sul nome di una classe o di una struct apri Alt+Shift+Q › Class Hierarchy... (o Extensions › UnrealSense › Class Hierarchy...; la voce compare solo sul nome di una classe). Si apre un menu a tendina, dove si trova il mouse, con la classe, le sue classi base dalla più vicina (per esempio ACharacter, APawn, AActor, UObject, interfacce comprese) e le classi derivate ad albero, con le linee dei livelli e accanto a ogni classe quante sottoclassi ha. Le classi con sottoclassi si chiudono e si aprono con un clic sulla freccia o con ←/→ (Ctrl+←/→ tutte); con più di 40 derivate all'apertura è aperto solo il primo livello. Clic su una (o frecce su/giù e Invio) apre il suo file sulla classe; scrivendo filtri l'elenco (le classi trovate restano sotto le loro classi padre).

Le classi dell'engine vengono dall'indice C++ di UnrealSense, che conosce gli header dell'engine inclusi dal progetto: le basi sono sempre complete, le derivate dell'engine sono quelle di quegli header (tutte con Index the whole engine). Le derivate di classi molto comuni come UObject si fermano a 2.000. Finché l'indice si costruisce compaiono solo le classi UCLASS/USTRUCT del progetto.

Funzione base e override

Con il cursore su una funzione virtual, su un override o su un evento UFUNCTION, al posto di Class Hierarchy... il Quick Menu mostra Base and Overrides of X.... Finché il menu a tendina è aperto, il nome a cui si riferisce (classe o funzione) è evidenziato in arancione nell'editor. Il menu a tendina elenca la funzione, le funzioni base che sovrascrive fino a quella che la introduce (segnata origin, per esempio AActor::BeginPlay) e gli override nelle sottoclassi, ad albero. Una BlueprintNativeEvent viene seguita attraverso i suoi _Implementation: dal cursore su ChoosePlayerStart si vedono la sua implementazione e gli ChoosePlayerStart_Implementation delle sottoclassi, e da uno di questi si risale alla UFUNCTION. Per gli eventi compaiono anche le Blueprint che li implementano; su una BlueprintImplementableEvent la voce si chiama Blueprint Implementations of X.... Clic su una funzione apre il suo file, clic su una Blueprint la apre nell'Unreal Editor. Serve l'indice C++ di UnrealSense.

Aggiungere un #include o una forward declaration

Con il cursore su un nome apri Alt+Shift+Q › Add #include: UnrealSense aggiunge l'#include del suo header scritto come nel codice Unreal ("GameFramework/Actor.h"), dopo gli altri include e prima del .generated.h. Per una classe, struct o enum è il suo header; per una variabile o una funzione l'header che la dichiara se il file non lo vede ancora, altrimenti quello del suo tipo (TObjectPtr<UMyComponent> Comp → l'header di UMyComponent).

In un header compare anche Add Forward Declaration: scrive class UMyComponent; (o struct, enum class EMode : uint8;, dentro il suo namespace) dopo gli include o vicino alle altre forward declaration. Template, classi annidate ed enum senza tipo sottostante non si possono dichiarare così: lo dice la barra di stato. Serve l'indice C++ di UnrealSense.

Unreal Explorer

Menu Extensions › UnrealSense › Unreal Explorer (o View › Other Windows). Mostra i moduli del progetto, i plugin, i Blueprint raggruppati per classe C++ di origine e i file di configurazione, con una casella di ricerca.

Creare una nuova classe Unreal

In Esplora soluzioni clic destro su un progetto o una cartella › Aggiungi › Unreal Class... (oppure Extensions › UnrealSense › Unreal Class..., o il pulsante New class dell'Unreal Explorer). Scegli il nome (il prefisso A/U/F/E lo aggiunge UnrealSense), la classe padre (Common per le più usate, All Classes per tutte quelle di progetto, plugin ed engine) e la cartella: Public mette il .h in Public e il .cpp in Private.

Il percorso può essere in qualsiasi modulo (una cartella con un .Build.cs, o sotto): progetto, suoi plugin, engine o plugin dell'engine. Parte dalla cartella del file aperto nell'editor (o da quella selezionata in Esplora soluzioni); il pulsante ... apre un selettore con le cartelle dei sorgenti di progetto, plugin ed engine ad albero, con moduli e plugin segnati, e una ricerca per nome di modulo.

I file nascono come quelli dell'Unreal Editor (<MODULO>_API, include giusti, funzioni tipiche del padre), vengono aggiunti al progetto e aperti. Se manca la dipendenza dal modulo del padre (per esempio UMG), una casella propone di aggiungerla al .Build.cs. Gli include restano rossi finché non esegui Generate Project Files; il .generated.h esiste dopo la prima compilazione.

Impostazioni

In Tools › Options › UnrealSense. In Visual Studio 2026 è una pagina della nuova finestra delle impostazioni (Tutte le impostazioni › UnrealSense, divisa per sezioni, con i valori che avevi già); in Visual Studio 2022 resta la pagina classica. Le più utili:

Show Blueprint usage hints Accende o spegne le scritte grigie nel codice.
Show hints for unused Blueprint API Mostra anche "no Blueprint usages" sulle funzioni e proprietà esposte ai Blueprint ma mai usate: utile per fare pulizia.
Unreal project Da impostare solo se UnrealSense apre il progetto sbagliato (capita con soluzioni che ne contengono più di uno).
IntelliSense errors in Unreal files HideFalse di default nasconde gli errori falsi di IntelliSense; HideAll li nasconde tutti; ShowAll lascia quelli di Visual Studio.
Member completion after . and -> Accesa di default: spegne solo il completamento dei membri dopo . e ->.
Name completion (locals, members, types, macros) Accesa di default: spegne il completamento dei nomi mentre li scrivi, dopo :: e dentro #include.
Add missing #include Accesa di default: spenta, scegliere un nome non aggiunge l'include che manca.
Don't wait for Visual Studio's C++ list Accesa di default: dove UnrealSense propone i nomi non chiede la lista di IntelliSense, quindi la lista compare appena risponde il nostro indice invece di aspettare IntelliSense (lento dopo una modifica a un header o con molti progetti caricati). Dove il nostro indice non ha niente si apre la lista di Visual Studio. Spenta, la lista unisce di nuovo le due (e aspetta IntelliSense). Visual Assist non cambia.
UI theme Unreal di default (stile dell'editor di Unreal); Classic usa i colori di Visual Studio e ne segue il tema.
UnrealSense colorization Accesa di default: spenta, tornano i colori di Visual Studio, subito anche nei file aperti.
Semantic colours from the own index Accesa di default: spenta, restano solo i colori che non vengono dall'indice (token e prefissi Unreal).
Go to definition (Ctrl+click, F12) Accesa di default: spenta, Ctrl+clic e F12 tornano a Visual Studio.
Use the own C++ index Accesa di default. Serve al completamento dei membri e delle variabili locali (spenta, il completamento non c'è) e accende Find Usages (menu contestuale dell'editor e Extensions › UnrealSense): trova dove un simbolo C++ è usato con un indice scritto da noi, anche dentro le macro (argomenti di UE_LOG, check, AddDynamic, corpo di un #define del progetto, UPROPERTY(ReplicatedUsing = OnRep_X)). La prima volta UnrealSense fa generare a UnrealBuildTool il database di compilazione (circa un minuto) e l'indice si costruisce in pochi secondi; poi l'indice resta su disco e dopo ogni salvataggio di un file C++ rilegge solo i file cambiati (se non hai aggiunto o tolto dichiarazioni riusa i simboli già noti: con Lyra e tutto l'engine circa 1 secondo, circa 4 se una dichiarazione cambia). Gli usi su oggetti di tipo non riconosciuto sono in fondo ai risultati, sotto Uncertain. Index the whole engine (attiva di default) aggiunge tutti i sorgenti dell'engine (circa 100.000 file); se la spegni indicizza solo gli header dell'engine inclusi dal progetto. In Task Manager compare come usindex: durante una build usa più memoria, poi la restituisce (per un progetto come Lyra circa 0,3 GB; con tutto l'engine circa 3,5 GB in Task Manager, di più con un engine più grande).
